# SEO-платформа — Этап 4: карточки, фильтры, конверсия, AI

> Дата: 11.07.2026. Предыдущие этапы подтверждены. Числа — из принятой
> выгрузки: бюджетные позиции есть у 1 398 из 1 785 вузов (78%), платные с
> известной ценой — у 1 516 (85%), правила приёма по ссылке — у 99%.
> Медиана очного платного бакалавриата — 190 тыс. ₽/год
> (квартили 158–270 тыс.).

Новая находка для конвейера импорта (дополнение к Д6): 11 позиций очного
бакалавриата со стоимостью 1–513 ₽ — мусор источника. Правило: стоимость
ниже санитарного порога (20 тыс. ₽/год) при импорте помечается как
«Информация отсутствует» и попадает в журнал ручной проверки.

## 1. Карточки

Общие правила всех карточек: пробел данных показывается явно («Информация
отсутствует»), не прячется и не заполняется; каждый факт прослеживается до
поля выгрузки; подпись источника и дата — в подвале карточки (этап 2);
конверсионные зоны — только из реестра целей (этап 1, Р2).

**Карточка вуза** (сверху вниз):
1. Шапка: короткое имя (заголовок), полное имя, хлебные крошки
   Главная → Регион → Город → Вуз; для филиала — ссылка на головной
   (когда связь заполнена; до того — без ссылки, этап 1). Бейджи фактов:
   «Есть бюджетные места» / «Общежитие» / «Военная кафедра» — только
   истинные флаги, отсутствие флага не рисуется как минус.
2. Факт-лента: направлений (счёт из списка программ), уровни, вилка
   стоимости платных, места в общежитии (у 38% — у прочих пробел),
   контакты, официальный сайт.
3. Программы — главный блок: группировка уровень → группа УГСН →
   направление; в строке: направление (ссылка на его страницу/комбо),
   форма, бюджетные места (сумма по КЦП и квотам с раскрытием по типам),
   платные места, стоимость. Внутрикарточные фильтры: уровень, форма,
   «только с бюджетом». На 200+ позициях — свёртка групп по умолчанию.
4. Приёмная кампания: имеющиеся полезные ссылки источника (правила приёма,
   апелляции, достижения, олимпиады — до 24 видов, показываются существующие).
5. FAQ из фактов (этап 2) + JSON-LD.
6. «Рядом и похоже»: вузы того же города с пересечением по УГСН;
   филиалы/головной.
7. Конверсионная вставка (раздел 4) — после блока программ, не раньше:
   пользователь сначала получает пользу.
   Для 9 ординатурных медцентров — честная плашка вместо блока программ
   (этап 1).

**Карточка направления (ОКСО)**: код и название; уровни, на которых оно
существует, с перекрёстными ссылками (09.03.01 ↔ 09.04.01 — «продолжение в
магистратуре»); города и вузы (таблица с фильтром по городу/форме/бюджету);
вилка стоимости; комбо-ссылки на «направление × город» с ≥2 вузами.
Описательный текст «что это за специальность» — редакционный слот
(в базе описаний нет; автотекст запрещён).

**Карточка города**: агрегаты (вузов, направлений, вилка цен), список вузов
(строки каталога), направления с ≥2 вузами, кураторские посадочные города,
ссылка на регион и города-соседи по региону. Для 185 одновузовых городов
карточка честно короткая: вуз, регион, направления вуза.

**Карточка региона**: города региона с числом вузов, сводные агрегаты,
направления региона (≥2 вузов и ≥2 городов — этап 2).

**Карточка УГСН**: направления группы со счётчиками вузов, топ-города
группы; редакционный слот для обзора группы.

## 2. Фильтры каталога

Панель (десктоп — слева, мобильный — шторка снизу):

- География: регион → город (двухуровневый, с поиском по названию).
- Направление: УГСН → направление (с поиском; выбор направления
  переключает каталог в режим «вузы с этим направлением»).
- Уровень (обе системы уровней — этап 1), форма обучения.
- Бюджет: «есть бюджетные места» (78% вузов), тип мест (квоты — раскрытие
  для продвинутых).
- Стоимость: слайдер с гистограммой распределения (данные есть — 42,7 тыс.
  платных позиций), границы по фактическим квартилям, а не круглым числам.
- Общежитие, военная кафедра — переключатели.

Правила поведения (уровень Booking):
- Счётчик результата на каждом значении фильтра («Москва (336)») из
  фасетных агрегатов витрин; пересчёт при каждом изменении.
- Значения с нулевым результатом в текущей комбинации гаснут — нулевую
  выдачу нельзя получить кликами.
- Применение мгновенное, без перезагрузки; кнопка «Показать N вузов» на
  мобильном; сброс всего и каждого фильтра отдельно.
- Состояние фильтров сериализуется в параметры адреса в каноническом
  порядке (шаринг ссылкой работает); индексационные правила — этап 2:
  noindex + canonical, внутренние ссылки на параметры не ставятся.
- Сортировки: по алфавиту, по числу направлений, по мин. стоимости
  (позиции без цены — в конец, не как 0 ₽). «По рейтингу» не существует —
  рейтингов нет в данных.

## 3. Сравнение, избранное, персонализация — без аккаунта

Всё хранится в браузере пользователя (решение этапа 1: ПДн несовершеннолетних
не собираем; сервер не знает пользователя):

- Сравнение: до 4 вузов; строки — только факты базы: город, уровни, число
  направлений, бюджетные места, вилка стоимости, общежитие (и места),
  военная кафедра, пересечение направлений (что есть в обоих). Пустая
  ячейка — «Информация отсутствует». Страница noindex, ссылка шарится
  (состав сравнения в адресе).
- Избранное: вузы и направления; вход из шапки; экспорт — просто ссылка.
- Недавно просмотренные: последние 10 сущностей, блок на главной и в
  каталоге.
- «Мой город»: явный выбор пользователя; влияет на порядок выдачи поиска
  (этап 3) и первый экран каталога; никогда не определяется геолокацией
  без запроса.
- Рекомендации — только контентные, из витрин: «похожие вузы» (тот же
  город + пересечение УГСН), «похожие направления» (та же УГСН, доля
  общих вузов), «продолжение уровня» (бакалавриат ↔ магистратура кода).
  Поведенческого профилирования нет.

## 4. Конверсионная система

Рамка (главный принцип задания): сайт помогает решить, а не продаёт вуз.
Пользователь приходит за фактами → получает их полностью → сталкивается с
главной развилкой («факты не говорят, что подходит именно тебе») → мост к
диагностике. CTA формулируются как следующий шаг решения, без рекламного
тона.

Слои:
1. **Микрововлечение** (без конверсионного давления): сравнение, избранное,
   фильтры, «мой город». Цель — возврат и глубина.
2. **Контентные вставки** (в карточках после полезных блоков, в каталоге
   после 10-й строки): один экран, одна мысль — «как правильно выбирать»;
   ведут на квиз или статью-мост.
3. **Квиз** `/test/` — центральный мост: 5–7 вопросов без ПДн (класс,
   определённость выбора, что уже решено — город/направление/вуз,
   интересующие группы УГСН). Исход двухветочный: «знаю, кем стать» →
   маршрут по платформе (подборка направлений и вузов из витрин);
   «не знаю» → объяснение, почему дальше нужен инструмент глубже
   (оцифровка сильных сторон), и переход на цель из реестра с UTM.
   Названия методик диагностики в текстах не употребляются (правило
   проекта о переименовании тестов). Результат квиза живёт в браузере.
4. **Размещения целей** (реестр этапа 1): закреплённая кнопка на карточках
   (появляется после 40% прокрутки, место зарезервировано — без сдвига
   макета); вставка после блока программ; финальный экран квиза; выходной
   слой (exit-intent, только десктоп, максимум 1 раз за сессию) —
   предлагает квиз, не покупку.
5. **Возражения и доказательства**: блок «зачем понимать себя до выбора
   вуза» строится на логике маршрута. Кейсы, отзывы, цифры результатов —
   **слот до появления реальных материалов MainExperts**; выдумывать и
   обезличенно «социально доказывать» запрещено. (Гипотеза моста
   «факты → осознание → диагностика» не валидирована — это ставка проекта,
   отмечено в этапе 0; квиз — её первый измеритель.)

Эксперименты: перестановки текстов/позиций размещений через реестр
(вариант = поле размещения); на старте трафика эксперименты
последовательные (неделя A / неделя B), параллельное разбиение — после
достижения объёма, при котором минимально детектируемый эффект считается
за ≤2 недели (расчёт по фактической базовой конверсии, не по желаемой).
Метрика эксперимента — клик по цели и глубина пути до него.

## 5. AI-помощник

Контур: диалог поверх витрин базы. Ответ собирается только из фактов
найденных сущностей, каждый факт в ответе сопровождается ссылкой на
сущность-источник; на вопрос вне данных — стандартное «В данных платформы
этого нет» плюс маршрут (какой раздел/фильтр поможет). После содержательной
консультации — мягкое предложение следующего шага (цель из реестра),
не чаще одного раза за диалог.

Ограничения: переписка не привязывается к личности и не хранится дольше
сессии; ПДн не запрашиваются; для несовершеннолетних — те же правила без
исключений. Тон — по правилу платформы: помогает решить, не продаёт.

Статус: **слот, не входит в первый запуск.** Единственный блок платформы с
постоянной операционной стоимостью (вызовы модели); включается отдельным
решением после ответа C8 (бюджет). Проектное место зарезервировано:
точка входа в шапке и на карточках, деградация — на поиск и квиз.

## 6. Итог этапа

1. **Решение.** Пять типов карточек на фактах с явными пробелами; фильтры
   с фасетными счётчиками и запретом нулевой выдачи; сравнение/избранное/
   рекомендации без аккаунта и без поведенческого профилирования;
   четырёхслойная конверсионная система с квизом-мостом и настраиваемыми
   целями; AI-помощник — спроектированный слот с отложенным включением.
2. **Альтернативы.** Личный кабинет против браузерного хранения — выбран
   браузер (ПДн несовершеннолетних, скорость запуска); модальные CTA против
   встроенных — выбраны встроенные (принцип «сначала польза», Core Web
   Vitals); немедленный запуск AI против слота — слот (стоимость не
   утверждена).
3. **Причины выбора.** Аудитория и правовой контур (этап 0, докс 05);
   главный принцип задания; неготовность C8.
4. **Риски.** Мост «квиз → внешняя цель» теряет пользователя при переходе
   между доменами (смягчение: UTM + понятный текст перехода); гипотеза
   конверсии не валидирована — квиз является её измерителем, а не
   доказательством; кейсов и отзывов нет — блок доказательств слабее
   типового рынка до появления материалов.
5. **Ограничения.** Ни одного выдуманного факта в карточках и ответах
   помощника; названия методик диагностики не публикуются; сервер не
   хранит профили пользователей.
6. **Критерии качества.** Любая карточка с неполными данными читается
   осмысленно (проверка на 9 ординатурных, на вузах без цен и без
   общежития); фильтрами невозможно получить пустой список; каждый CTA
   ведёт на активную цель реестра с корректным UTM; квиз проходится
   за ≤2 минут.
7. **Checklist готовности.** [x] Состав и состояния карточек всех пяти
   типов. [x] Правила фильтров и сортировок. [x] Хранение без аккаунта.
   [x] Конверсионные слои, квиз, эксперименты. [x] Контур AI-помощника и
   условия включения. [x] Санитарное правило цен добавлено в конвейер
   импорта. [ ] Подтверждение владельца → этап 5.

**Этап 5 (после подтверждения):** технологии и данные — сравнение стеков
(SSR/SSG/ISR, фронт и сервер), схема базы (ER, индексы, версии), API
(REST против GraphQL), административная панель (роли, права, реестр целей,
кураторские посадочные, редиректы, журнал изменений). Для финальной
ратификации стека нужен ответ C8 (бюджет, команда сопровождения);
без него этап выдаст решение с помеченным допущением.
