# ingest — приём файла в хранилище

Канон знаний — `docs/01–07`. Новое из загрузок кладётся в `vault/` и связывается с
каноном; сам канон правится осознанно (шаг 7). Синтез, не пересказ.

## Шаги
0. **Текст.** Drive — `mcp__Google_Drive__read_file_content`; локальный файл —
   `python3 scripts/extract.py <путь>`. Большой PDF — постранично.
1. **Источник.** id `ГГГГ-ММ-ДД-ЧЧММ-kebab`. Создай `vault/10-sources/<id>.md` из
   `_templates/source.md`: происхождение, дата, ссылка, число страниц, конспект
   5–10 строк, карта разделов. Полный текст не копировать. Сырьё — в `raw/`.
2. **Сверка с каноном.** Прежде чем плодить заметки, пройди `docs/` (поиск `rg`):
   что уже известно, что ново, что противоречит. Противоречие с каноном — назвать вслух.
3. **Атомарные заметки.** На каждую новую мысль — `vault/20-notes/<id>-NN.md` из
   `_templates/note.md`: одна мысль своими словами; происхождение (`source_ref`,
   `source_date`, `source_url`); `stream`; `status` (вывод на гипотезе скрининга →
   `гипотеза`; факт без источника → `требует-проверки`); `goal`, если про экспертов;
   метки; ссылки на смежные заметки, сущности и нужные разделы `docs/`.
4. **Сущности.** Обнови/создай `vault/30-entities/`. Профессии — с кодами O*NET/ESCO.
5. **Связи.** Двусторонние `[[ссылки]]`; добавь записи в `vault/00-index/MOC.md`.
6. **Контроль правил:** каждый факт с источником; потоки не смешаны; гипотеза
   помечена; тесты переименованы в клиентских формулировках.
7. **Обновление канона.** Если материал меняет факты уровня канона — предложи правку
   конкретного `docs/0X.md` и обновление снимка `memory/memory.md`; для Диска — новая
   версия памяти плюс указание, какой файл удалить вручную (правило двух версий).
8. **Доклад:** id источника, сколько заметок/сущностей, что осталось `требует-проверки`.
9. **Закрой проверкой:** к какому из двух потоков и к какой из трёх целей относится материал.
