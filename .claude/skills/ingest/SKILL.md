# ingest — приём файла в хранилище

Цель: дистиллировать сырьё в связные заметки, чтобы дальше работать с заметками,
а не с файлом. Синтез, не пересказ.

## Шаги

0. **Получить текст.** Файл в Drive — `mcp__Google_Drive__read_file_content`
   (Docs/PDF/docx → текст). Локальный файл — `python3 scripts/extract.py <путь>`.
   Большой PDF — постранично.

1. **Завести источник.** id вида `ГГГГ-ММ-ДД-ЧЧММ-kebab`. Создай
   `vault/10-sources/<id>.md` из `_templates/source.md`: заголовок, происхождение
   (автор/встреча/выгрузка), дата, ссылка Drive, число страниц, конспект 5–10 строк,
   карта разделов. **Полный текст не копировать.**

2. **Архив сырья.** Если файл локальный — положить в `raw/<id>.<ext>`.

3. **Атомарные заметки.** На каждую отдельную мысль — `vault/20-notes/<id>-NN.md`
   из `_templates/note.md`:
   - одна мысль, своими словами (синтез);
   - обязательные поля происхождения: `source_ref` (стр.), `source_date`, `source_url`;
   - `stream` (поток-1 / поток-2 / общее) — обязательно;
   - `status`: вывод на гипотезе скрининга → `гипотеза`; факт без источника →
     `требует-проверки`;
   - `goal`, если заметка про привлечение экспертов (валидация / гипотеза-скрининга / опыт);
   - метки из `tags.md`, ссылки на смежные заметки и сущности.

4. **Сущности.** Обнови/создай `vault/30-entities/` (персонажи ЦА, концепции,
   профессии, команда). Профессии связывай с кодами O*NET/ESCO, если есть.

5. **Связи.** Проставь двусторонние `[[ссылки]]` в заметках и добавь записи в
   нужные разделы `vault/00-index/MOC.md`.

6. **Контроль правил** перед завершением: каждый факт с источником; потоки не
   смешаны; гипотеза помечена; тесты переименованы в клиентских формулировках.

7. **Доклад.** id источника; сколько заметок и сущностей создано; что осталось
   `требует-проверки`. Если появились факты уровня памяти — предложи обновление
   `memory/memory.md`.

8. **Закрой проверкой:** к какому из двух потоков и к какой из трёх целей относится
   материал.
