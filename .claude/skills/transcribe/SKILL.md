# transcribe — расшифровка записи по голосам

Локальный пайплайн на процессоре: запись не уходит наружу. Код и подробности —
`scripts/transcribe/README.md`.

## Шаги

1. **Окружение.** `scripts/transcribe/setup.sh` — ffmpeg, пакеты, модели диаризации.
   Контейнер эфемерный, после пересоздания ставится заново.
2. **Файл.** С Google Drive качать напрямую, не через MCP: `download_file_content`
   отдаёт base64 в контекст и на записи в сотни мегабайт непригоден.
   ```bash
   ID=<file_id>
   curl -sSL -c /tmp/cj "https://drive.google.com/uc?export=download&id=$ID" -o /tmp/p.html
   # взять из формы uuid и confirm, затем:
   curl -sSL "https://drive.usercontent.google.com/download?id=$ID&export=download&confirm=t&uuid=<uuid>" -o raw/<имя>.webm
   ```
   Сверить размер с метаданными Drive. Сырьё — в `raw/` (вне git).
3. **Прогон.** Заранее посмотреть длительность (`ffprobe`) и предупредить о времени:
   считается примерно как длительность записи.
   ```bash
   nohup python3 scripts/transcribe/diarize_asr.py raw/<файл> -o transcripts/ > /tmp/tr.log 2>&1 &
   ```
   Число участников, если известно, задавать ключом `-s N` — точность разметки выше.
4. **Имена.** Если запись сделана в Telemost, Meet или Zoom — сначала разметка по
   картинке, она даёт настоящие имена участников:
   ```bash
   python3 scripts/transcribe/video_speaker_tags.py raw/<файл> -o transcripts/.work/<имя>.tags.json
   python3 scripts/transcribe/diarize_asr.py raw/<файл> -o transcripts/ --video-tags transcripts/.work/<имя>.tags.json
   ```
   Написание имён сверить с кадром (OCR путает буквы), поправки — в
   `transcripts/<файл>.names.json`, пересборка с `--names` идёт из кеша за секунды.
   Записи без видео: прогон даёт «Говорящий 1…N», соответствие выводится из первых
   минут (представления, обращения по имени). Такая атрибуция — предположение,
   помечать как таковое, не выдавать за факт.
5. **Выдача — всегда три файла разом, без напоминания:**
   - `<имя>.md` — полный транскрипт с таймкодами и говорящими;
   - `<имя>.txt` — то же содержание без разметки (скрипт делает сам);
   - `<имя>.summary.html` — выжимка, её собираешь ты, прочитав транскрипт целиком.

   Выжимка пишется так, чтобы по ней можно было ставить задачи, не открывая расшифровку:
   шапка (встреча, дата, участники, предмет) → **закреплено** (решения) → **числа**
   (таблица величин со смыслом каждой) → **задачи** (блоками по исполнителям, каждая —
   что сделать и зачем) → **не решено** (развилка и что её закроет) → **риски**
   (названные участниками, не додуманные). Каждый пункт с таймкодом — чтобы
   проверялся по записи за секунды. Ничего не добавлять от себя: чего на встрече
   не было, того в выжимке нет; путаницу в обозначениях называть прямо.
   Вёрстка простая и печатаемая, светлая и тёмная темы, без внешних зависимостей.

   Тяжёлые `.wav` и кеш `transcripts/.work/` в git не идут.
6. **Дальше по системе.** Транскрипт встречи — материал для хранилища: предложить
   `ingest` (заметки в `vault/`) и, если встреча меняет факты уровня канона, правку
   `docs/`. Публикация артефакта — скилл `publish`.

## Что говорить о качестве

Не выдавать транскрипт за протокол. При выдаче назвать прямо: перекрывающаяся речь
приписывается одному голосу, короткие вставки липнут к соседу, термины и суммы
распознаются с ошибками. Цифры, цитаты и имена, идущие в материалы клиентам,
сверяются с записью.
