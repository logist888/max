# transcribe — расшифровка записи по голосам

Локальный пайплайн на процессоре: запись не уходит наружу. Это принципиально —
на записях имена клиентов, цены и данные несовершеннолетних. Устройство и
подробности — `scripts/transcribe/README.md`.

## Быстрый путь

```bash
scripts/transcribe/setup.sh                                  # один раз на контейнер
scripts/transcribe/fetch.sh raw/Встреча-2026-09-29 ID1 ID2   # части по порядку времени
scripts/transcribe/join.sh raw/Встреча-2026-09-29.webm raw/Встреча-2026-09-29-p*.webm
nohup scripts/transcribe/run.sh raw/Встреча-2026-09-29.webm \
      --participants "Игорь А.,Александр Бондаренко" -s 4 -e titanet > /tmp/tr.log 2>&1 &
```

`run.sh` сам считает разметку по картинке, потом распознавание. Дальше остаётся
прочитать транскрипт целиком и собрать выжимку.

## Шаги

1. **Окружение.** `scripts/transcribe/setup.sh` — ffmpeg, пакеты, модели диаризации.
   Контейнер эфемерный, после пересоздания ставится заново. Модель распознавания
   (1,6 ГБ) скачивается сама при первом запуске.

2. **Файлы.** Ссылка ведёт на папку — получить список через MCP
   `search_files` с запросом `parentId = '<id папки>'` (поле `parents` этот
   инструмент не понимает) и не забыть `nextPageToken`: страница отдаёт по пять
   файлов, а частей бывает семь. Скачивать `fetch.sh`, не через MCP:
   `download_file_content` отдаёт base64 в контекст и на записи в сотни мегабайт
   непригоден. Размеры сверить с метаданными Drive. Сырьё — в `raw/`, вне git.

3. **Склейка.** Несколько частей одной встречи — сразу в один файл через `join.sh`,
   в порядке времени начала. Клиенты режут запись кусками по 30 минут; на стыках
   теряются секунды, а между кусками бывает и реальный перерыв в несколько минут.
   В склейке пауз нет, поэтому таймкоды уходят вперёд относительно живого времени
   встречи — это пишется в шапку выжимки.

   **Длительность webm врёт.** Заголовок контейнера после concat показывает
   меньше реального; правду говорит последний пакет аудио
   (`ffprobe -select_streams a -show_entries packet=pts_time`) или длина WAV после
   конвертации. Проверять до того, как называть длительность Игорю.

4. **Прогон.** Считает примерно вчетверо быстрее реального времени: три часа
   записи — около часа распознавания плюс полтора часа диаризации. Предупредить
   заранее. Ключи `run.sh` уходят в `diarize_asr.py`, кроме двух:

   | Ключ | Смысл |
   |---|---|
   | `-s N` | известное число говорящих — точность разметки выше |
   | `-e titanet` | тяжёлая модель эмбеддингов: похожие голоса, эхо, перебивки |
   | `--participants "А,Б,В"` | известный состав для разметки по картинке |
   | `--band N` | высота полосы плиток; 1080 — вся сетка на экране |
   | `--video-only` | не подмешивать голос, только подсветка |
   | `--video-names-only` | взять из видео имена, границы реплик — по голосу |
   | `--names f.json` | ручная карта имён, перекрывает всё остальное |

5. **Имена.** В Telemost, Meet и Zoom подсвечена плитка говорящего, а под ней
   подпись — это источник надёжнее кластеризации голосов, потому что привязан к
   участнику, а не к тембру. `run.sh` включает его сам, когда в файле есть видео.

   **Состав лучше задать явно.** Посмотреть кадр
   (`ffmpeg -ss 600 -i запись.webm -frames:v 1 кадр.png`), прочитать имена глазами
   и передать `--participants`. Без этого в участники попадают заголовки
   демонстрируемых слайдов: зелёные линии вёрстки в документе неотличимы от рамки
   подсветки, а их подпись повторяется достаточно часто, чтобы сойти за имя.

   **Сигнал проверять до того, как на него опереться.** Если участник ведёт
   демонстрацию экрана, его плитка может гореть всё время показа независимо от
   того, кто говорит. Признак подмены: одно имя на большую часть записи при живом
   разговоре. Тогда `--video-only` отключить и считать по голосу.

   Записи без видео дают «Говорящий 1…N»; соответствие выводится из первых минут
   по представлениям и обращениям. Это предположение, так и помечать.

   Поправки написания — в `transcripts/<файл>.names.json`, пересборка с `--names`
   идёт из кеша за секунды. Пересобирать что угодно дёшево: в `transcripts/.work/`
   лежат WAV, диаризация, слова и теги; повторный прогон их подхватывает.

6. **Достоверность.** Скрипт печатает её в шапке транскрипта. Когда большинство
   слов размечено по подсветке — доля прямой разметки; оговорка про смены без
   паузы относится только к остатку, размеченному по голосу. Когда видео не
   использовалось — доля смен говорящего без паузы: выше 25 % роли перепроверять,
   выше 50 % не выдавать за факт.

7. **Выдача — всегда три файла разом, без напоминания:**
   - `<имя>.md` — полный транскрипт с таймкодами и говорящими;
   - `<имя>.txt` — то же содержание без разметки (скрипт делает сам);
   - `<имя>.summary.html` — выжимка, её собираешь ты, прочитав транскрипт целиком.

   Каркас выжимки — `assets/summary.html` рядом с этим файлом: вёрстка, светлая и
   тёмная темы, готовые блоки. Копировать его и заполнять, а не верстать заново.
   Структура: шапка (встреча, дата, участники, предмет, кто сколько говорил) →
   **главное** → **числа** (таблица величин со смыслом каждой) → **закреплено**
   (решения) → разделы по существу (возражение, сбой, предложение) → **задачи**
   блоками по исполнителям → **не решено** (развилка и что её закроет) → **риски**
   (названные участниками, не додуманные). Каждый пункт с таймкодом — чтобы
   проверялся по записи за секунды. Ничего не добавлять от себя: чего на встрече
   не было, того в выжимке нет; путаницу в обозначениях называть прямо.

   Транскрипт читать целиком, а не по диагонали: на длинной записи решение часто
   прячется в одной реплике посреди разговора ни о чём.

   Тяжёлые `.wav` и кеш `transcripts/.work/` в git не идут.

8. **Дальше по системе.** Транскрипт встречи — материал для хранилища: предложить
   `ingest` (заметки в `vault/`) и, если встреча меняет факты уровня канона, правку
   `docs/`. Публикация артефакта — скилл `publish`.

## Если пошло не так

| Симптом | Причина | Что делать |
|---|---|---|
| Процесс убит, в логе ничего после «распознавание: N мин» | не хватило памяти | распознавание идёт кусками по 15 минут (`CHUNK`); если всё равно падает — уменьшить |
| Разметка по картинке ползёт часами | подписи не попадают в кеш или кроп во всю ширину плитки | норма — 10 минут записи за 20 секунд; иначе смотреть `stable_key` и `trim_to_text` |
| В участниках заголовки слайдов | зелёная вёрстка документа принята за подсветку | задать `--participants` |
| Один человек под разными именами | мелкая подпись в полосе плиток читается огрызками | `--participants` сводит их по сходству; узнавание по аватарке добирает остальное |
| Реплик втрое больше разумного | видеоразметка дробит речь по морганию подсветки | `--video-names-only` |
| Все голоса слились в один кластер | похожие голоса, эхо | `-e titanet`, при неудаче `--video-only` |
| Прогон начался с нуля, хотя уже считали | другой `-o` — кеш ищется рядом с выдачей | всегда `-o transcripts/` |

## Что говорить о качестве

Не выдавать транскрипт за протокол. При выдаче назвать прямо: перекрывающаяся речь
приписывается одному голосу, короткие вставки липнут к соседу, термины и суммы
распознаются с ошибками. Цифры, цитаты и имена, идущие в материалы клиентам,
сверяются с записью.
