# cjm-map: карта пути клиента (CJM) в SVG

Скилл собирает карту, как в образце `vault/40-reports/2026-11-03-cjm-poisk-vse-napravleniya-shema-i-stikery.svg`: сверху блок-схема с дорожками, этапами и шагами, под ней столбцы CJM (цели, действия, мысли, точки контакта, опыт, эмоции, идеи, вставки, экраны) в тех же колонках, что и у схемы. Всё берётся из одного файла `journey.yaml`.

## Запуск за 5 минут

Нужен Python 3. Проверено на 3.13; на более ранних версиях не запускалось.

```bash
pip install -r .claude/skills/cjm-map/requirements.txt
python .claude/skills/cjm-map/scripts/cjm_map/build.py .claude/skills/cjm-map/examples/journey.minimal.yaml --out out/minimal
```

В `out/minimal/` появятся `map.svg` и `map-text.svg`. Откройте любой в браузере.

| Флаг | Что делает |
|---|---|
| `--check` | только проверить данные |
| `--out папка` | куда класть результат (по умолчанию `out/`) |
| `--html` | `map.html` с кнопками масштаба и Ctrl + колесо |
| `--png` | `map.png` (до 4000 px) и `map-8000px.png` |
| `--pdf` | `map.pdf` |

`--png` и `--pdf` требуют Playwright: `pip install playwright && playwright install chromium`. Без него SVG и HTML собираются как обычно, а для PNG и PDF будет понятное сообщение. Если браузер лежит в нестандартном месте, задайте путь в `CJM_CHROMIUM`.

Самопроверка скилла: `python .claude/skills/cjm-map/scripts/selfcheck.py` (13 проверок, сборка двух примеров).

## Что получится

- `map.svg`: надписи переведены в контуры шрифта Inter, наконечники стрелок нарисованы многоугольниками, нет `<text>`, `<marker>`, `<filter>`, `<foreignObject>` и вложенных `<svg>`. Одинаково открывается в Figma, Miro, Illustrator, Inkscape и на телефоне. Минус: текст не выделить и не найти поиском.
- `map-text.svg`: те же формы, текст обычными `<text>` со шрифтом Inter (запасные Segoe UI, Arial). Выделяется и ищется, но на машине без Inter подставится другой шрифт, и строки могут чуть сдвинуться.
- Один и тот же файл данных всегда даёт побайтно один и тот же результат.
- Слои в файле обозначены группами: `backgrounds`, `screens`, `flowchart`, `arrows`, `stickies`. В Figma их удобно прятать по одному.

Шрифт Inter (латиница, кириллица, знаки) лежит в `fonts/`; лицензия SIL OFL 1.1 в `fonts/LICENSE-Inter.txt`.

## Устройство данных

Файл YAML с девятью разделами. Образец целиком: `examples/journey.example.yaml`; быстрый старт: `examples/journey.minimal.yaml`.

### meta
`title` (обязательно), `subtitle`, `flow_title` (заголовок над схемой, по умолчанию `title`), `date`, `version`, `source`.

### header (необязательно)
`job` (Job To Be Done), `assumption` (допущение), `drivers` и `barriers` (списки коротких фраз, зелёные и красные стикеры).

### lanes — дорожки схемы
`id` (уникальный), `label`, `style` 0–6 (цветовая схема: 0 жёлтая, 1 голубая, 2 синяя, 3 зелёная, 4 сиреневая, 5 оранжевая, 6 серая).

### stages — этапы
`id`, `label` (над схемой), `board_label` (над стикерами; по умолчанию как `label`), `from` и `to` (номера колонок, с нуля, включительно), `color`: `cyan`, `blue` или `#rrggbb`. Этапы не пересекаются. Ось времени одна: колонка у схемы и у стикеров общая.

### flow — блок-схема
- `lane_height` — высота дорожки, 120–600 (по умолчанию 240).
- `nodes` — шаги: `id`, `shape`, `col`, `lane`, `text`; необязательно `dy` (сдвиг по вертикали, px), `hypothesis: true` (пунктирная рамка), `style` (взять цвет другой дорожки).
- `edges` — связи: `from`, `to`; необязательно `ports` (две буквы: откуда и куда выходит стрелка, из `l r t b`; не указано — выберется само), `label`, `label_at: mid` (подпись посередине), `dash: true` (пунктир, возврат), `loss: true` (красная стрелка, выход или потеря клиента), `arrow: false`, `corridor: {lane: <id>, dy: <px>}` (обход по горизонтальному коридору на высоте центра дорожки плюс `dy`; для длинных возвратов, порты `bb` или `tt`).

Формы `shape` (нотация ГОСТ 19.701-90, ISO 5807):

| shape | значение |
|---|---|
| term | начало или конец |
| proc | действие, шаг |
| dec | решение, развилка |
| data | ввод или вывод данных |
| doc | документ, результат |
| db | база данных |
| manual | ручная операция |
| pre | подпроцесс правее |
| note | примечание |

Соответствие слову «тип шага»: действие = `proc`, развилка = `dec`, система = `db` или `proc` на дорожке системы, выход клиента = `term` с входящей стрелкой `loss: true`.

### rows — ряды CJM
`id`, `label`, `type`: `stack` (по умолчанию, стикеры стопкой в колонке), `goal` (стикеры этапа, раскладка по ширине этапа), `emotion` (три уровня, цветные поля, кривая настроения), `screens` (снимки экранов). Порядок рядов в файле — порядок на карте.

### stickies — стикеры
`row` (id ряда), `kind`, `text`; для `goal` — `stage` (id этапа), для остальных — `col`; для `emotion` — `level`: `1` радость, `0` нейтрально, `-1` боль. Необязательно: `id` (нужен для стрелок), `dy` (отступ сверху), `min_h` (минимальная высота).

| kind | цвет и смысл |
|---|---|
| y | жёлтый: шаг, мысль, идея |
| b | синий: ключевой переход |
| g | зелёный: драйвер, хороший опыт |
| r | красный: барьер, риск, боль |
| o | оранжевый |
| w | белый: точка контакта |
| gr | серый: пояснение, пробел |
| ghost | прозрачный пунктирный: гипотеза |
| ey | жёлтый насыщенный: нейтральная эмоция |

### sticky_links — стрелки между стикерами
`from`, `to` (id стикеров), необязательно `dash`, `loss` (красная).

### screens — строка «Экраны»
`col`, `span` (сколько колонок занимает), `image` (путь к JPEG или PNG относительно `journey.yaml`), `caption`. Нужен ряд с `type: screens`. Снимки вшиваются в SVG; делайте их шириной около 500 px, иначе файл станет тяжёлым. Нет файла — серая рамка и предупреждение.

## Как добавить

- **Дорожку:** строка в `lanes`, затем `lane: <id>` у шагов.
- **Этап (блок):** строка в `stages` с новыми колонками (следующие за последним этапом), шаги и стикеры с этими колонками.
- **Шаг и связь:** узел в `flow.nodes`, ребро в `flow.edges`.
- **Ряд CJM:** строка в `rows` и стикеры с этим `row`.
- **Стрелку между стикерами:** дайте обоим `id`, добавьте строку в `sticky_links`.

## Ошибки проверки

Сообщение имеет вид `файл:строка: путь.к.полю (id=…): что не так`. Примеры:

```
journey.yaml:31: flow.nodes[2] (id=ask): неизвестная дорожка «kosmos» (есть: client, site, team)
journey.yaml:44: flow.edges[6]: связь идёт к несуществующему шагу «nowhere»
journey.yaml:63: stickies[10]: поле «text» пустое
journey.yaml:37: flow.nodes[8] (id=n7): текст шага слишком длинный: 239 знаков при пределе 260
```

Ошибки YAML (`синтаксис YAML: …`) почти всегда значат, что текст с двоеточием или вопросом не взят в кавычки.

## Открыть SVG в Figma и Miro

Не проверялось в самих сервисах: в этой среде их нет. Ожидаемое поведение следует из устройства файла, а не из испытаний.

- **Figma:** `map.svg` без `<text>`, маркеров и фильтров (то, что обычно ломает импорт), тексты в нём контуры, править их нельзя. Для правок меняйте `journey.yaml` и собирайте заново. `map-text.svg` даёт редактируемый текст, но без шрифта Inter он может сместиться. Карта шириной около 19 700 px: если импорт тяжёлый, используйте PNG.
- **Miro:** вставьте `map-8000px.png` или SVG как изображение. Стикеры Miro из SVG не создаются.

## Ограничения

- Раскладка колонок фиксированная: ширина колонки 215 px, стикера 176 px. Шаги в одной колонке и одной дорожке налезают друг на друга: разнесите по `dy` или колонкам.
- Стрелки в схеме прокладываются простыми правилами (ломаная с одним или двумя изломами). Пересечения шагов возможны у длинных связей; используйте `corridor` и явные `ports`.
- Переносы строк считаются по метрикам Inter без кернинга; в `map-text.svg` браузер может сузить строки на 1–2 %.
- Стикеры в `stack`-ряду идут стопкой в порядке файла; сортировки нет.
- Эмоции на одном уровне в одной колонке налезут друг на друга: нужен разный `level` или колонка.
- Снимки в SVG встраиваются как `data:` URI; карта с 25 экранами весит около 10 МБ в контурном виде.
- Образец карты выгружен из прежних скриптов, поэтому раскладка близка к образцу (размер 19 711×5 621 против 19 750×5 587), но не побайтно равна.
