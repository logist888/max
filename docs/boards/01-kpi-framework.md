# 01. KPI-фреймворк: иерархия L0–L3, паспорт, дерево KPI

> Google Drive / MainExperts (`1.pdf` Том I, `2.pdf` Том II; владелец agafonov.agency,
> загр. 27.06.2026). Рабочий контекст — перед клиентскими материалами перепроверять с источником.

## Назначение

KPI Philosophy задаёт единый стандарт проектирования, расчёта, использования и развития всех показателей MainExperts. Главная задача KPI — не измерение бизнеса, а изменение качества управленческих решений. Любой показатель, который не влияет на решения, не является KPI: он может быть информационной метрикой, статистикой или техническим показателем, но в систему управления компанией не входит.

## Определение KPI

Key Performance Indicator (KPI) — количественный показатель, позволяющий оценить достижение конкретной бизнес-цели и принять управленческое решение.

Каждый KPI обязан отвечать пяти критериям:

1. Измеримость.
2. Однозначность трактовки.
3. Автоматический расчёт.
4. Наличие владельца.
5. Возможность управленческого воздействия.

Если отсутствует хотя бы один критерий, показатель не включается в корпоративный каталог KPI.

## Иерархия L0–L3

Все показатели организованы в многоуровневую систему. Каждый уровень отвечает на собственный набор вопросов; каждый руководитель работает только со своим уровнем, детализация выполняется через Drill Down по мере необходимости.

```
Level 0 — Strategic KPIs
   ↓
Level 1 — Management KPIs
   ↓
Level 2 — Operational KPIs
   ↓
Level 3 — Diagnostic Metrics
   ↓
Primary Events
```

| Уровень | Класс | Кто использует |
| --- | --- | --- |
| L0 | Strategic KPIs | Собственник и топ-менеджмент |
| L1 | Management KPIs | Руководители функций |
| L2 | Operational KPIs | Линейные руководители |
| L3 | Diagnostic Metrics | (для поиска причин; явный потребитель в источнике не назван) |

> Пробел: для каждого из уровней L0–L3 источник перечисляет «собственный набор вопросов», но сами вопросы по уровням не раскрыты.

### L0 — Strategic KPIs

Отражают состояние бизнеса в целом. Используются исключительно собственником и топ-менеджментом. Фиксируют результат, но не объясняют причины изменений. Основной набор:

- Revenue;
- Contribution;
- EBITDA;
- Operating Cash Flow;
- Runway;
- Enterprise Value;
- Customer Lifetime Value;
- Net Revenue Retention.

### L1 — Management KPIs

Используются руководителями функций.

| Функция | Показатели |
| --- | --- |
| Маркетинг | DRR; CAC; Conversion Rate; ROMI |
| Продажи | Win Rate; Average Deal Size; Sales Cycle |
| Экспертная сеть | Capacity Utilization; Average Rating; Repeat Sessions |
| Финансы | Gross Margin; Burn Rate; Cash Conversion |

### L2 — Operational KPIs

Используются линейными руководителями, применяются ежедневно. Например:

- количество консультаций;
- время ожидания клиента;
- количество новых экспертов;
- количество AI-запросов;
- скорость ответа поддержки.

### L3 — Diagnostic Metrics

Диагностические показатели не являются самостоятельной целью — они существуют исключительно для поиска причин. Каждый уровень декомпозиции приближает руководителя к первопричине проблемы. Пример цепочки:

```
Revenue
   ↓ Average Check
   ↓ Orders
   ↓ Traffic
   ↓ CTR
   ↓ Creative
```

## Паспорт KPI

Каждый показатель имеет обязательный паспорт. Состав:

| Раздел паспорта | Содержание |
| --- | --- |
| Общая информация | Код. Название. Описание |
| Формула | Полное математическое определение |
| Источник | Таблицы. API. Интеграции |
| Ответственный | Единственный владелец KPI |
| Частота обновления | Например: Online; каждые 5 минут; ежедневно; еженедельно |
| Пороговые значения | Норма. Предупреждение. Критическое значение |
| Drill Down | Последовательность раскрытия причин |
| Связанные KPI | Показатели, изменяющиеся вместе |

## Принцип дерева KPI

Ни один KPI не существует изолированно. Благодаря дереву система всегда способна найти причину отклонения; каждое изменение распространяется по дереву зависимостей. Примеры декомпозиции:

```
Revenue
   ↓ Clients
   ↓ Orders
   ↓ Payments
```

```
Contribution
   ↓ Revenue
   ↓ Variable Costs
        ↓ Expert Cost
        ↓ AI Cost
```

Раскрытие до первичного события (Принцип №3, Глава 3): любой показатель раскрывается до первичного события, пользователь всегда может установить происхождение значения.

```
Revenue
   ↓ Order
   ↓ Payment
   ↓ Transaction
   ↓ Source
```

## KPI Ownership

Каждый показатель имеет единственного владельца; ответственность не может быть коллективной. Владелец отвечает за:

- корректность расчёта (корректность данных);
- актуальность;
- интерпретацию;
- достижение целевых значений;
- развитие методики расчёта (разработку корректирующих мероприятий — формулировка Главы 3).

Изменение владельца фиксируется в журнале изменений.

## Жизненный цикл KPI

Любой показатель проходит стадии:

```
Proposal
   ↓ Approval
   ↓ Implementation
   ↓ Monitoring
   ↓ Optimization
   ↓ Archive
```

Новые KPI проходят обязательное согласование Архитектурным комитетом.

## Качество KPI

Для каждого KPI регулярно оцениваются:

- полнота данных;
- своевременность обновления;
- устойчивость формулы;
- количество ошибок;
- востребованность пользователями.

Показатели, не используемые в принятии решений, подлежат пересмотру.

## KPI и цели компании

Каждый KPI должен быть связан с одной из стратегических целей. Если KPI невозможно связать со стратегической целью, необходимость его существования пересматривается.

| Стратегическая цель | Основной KPI |
| --- | --- |
| Рост бизнеса | Revenue |
| Устойчивость | Runway |
| Эффективность | Contribution |
| Масштабирование | AI Share |
| Удержание клиентов | Retention |
| Качество | NPS |

## KPI и мотивация

KPI используются не только для анализа, но и для формирования системы мотивации. Принципы:

- один сотрудник не отвечает за показатель, который не может контролировать;
- показатели мотивации понятны исполнителю;
- нельзя стимулировать рост одного KPI за счёт ухудшения другого без явного управленческого решения.

> Оговорка: пример из источника — увеличение Revenue не должно достигаться ценой резкого роста Burn Rate или падения качества обслуживания.

## KPI и AI

AI использует каталог KPI как единственный источник интерпретации бизнеса. При обработке запросов AI:

- использует официальные определения показателей;
- соблюдает иерархию KPI;
- объясняет причины изменений через дерево зависимостей;
- формирует рекомендации только на основе утверждённых формул и данных.

AI не принимает окончательных управленческих решений и не изменяет бизнес-данные самостоятельно (Принцип №11, Глава 3). Этим исключается неоднозначность трактовки результатов.

## Принцип минимального набора KPI

Количество KPI должно быть минимально достаточным. Добавление нового показателя допускается только при выполнении всех условий:

1. Отвечает на новый управленческий вопрос.
2. Не дублирует существующие KPI.
3. Может быть автоматически рассчитан.
4. Имеет владельца.
5. Используется в принятии решений.

Рост количества KPI не должен усложнять систему управления.

## Управляющие принципы (Глава 3, выдержки про KPI)

Принципы Business Principles определяют логику управления: если KPI описывают состояние бизнеса, то принципы определяют логику его управления. Выдержки, грунтующие KPI-фреймворк:

| № | Принцип | Суть применительно к KPI |
| --- | --- | --- |
| 1 | Управление через решения, а не через отчёты | Каждый элемент отвечает на вопрос: какое управленческое решение станет проще принять благодаря этим данным? Без ответа — показатель избыточен |
| 2 | Один источник истины (Single Source of Truth) | Для каждого показателя — только одна официальная формула расчёта (Revenue, Contribution, Runway — единственным способом). Несколько трактовок одного показателя запрещены |
| 3 | Каждая цифра должна быть объяснима | Любой показатель раскрывается до первичного события (Revenue ↓ Order ↓ Payment ↓ Transaction ↓ Source) |
| 4 | Причина важнее симптома | Система выявляет причины, а не последствия; вся аналитика строится на деревьях декомпозиции KPI |
| 5 | Скорость принятия решений | Целевые значения скорости получения информации (см. ниже) |
| 9 | Ответственность за показатели | Каждый KPI имеет единственного владельца; ответственность не коллективна |

### Целевые значения скорости (Принцип №5)

| Класс информации | Целевая скорость |
| --- | --- |
| Критическая информация | Немедленно |
| Оперативные KPI | В течение нескольких минут |
| Стратегическая аналитика | Ежедневно |

Отчёт, подготовленный слишком поздно, теряет управленческую ценность независимо от точности.

### Матрица соответствия (Принцип, §3.14)

Каждый новый проект внутри MainExperts оценивается по вопросам (Да/Нет): поддерживает миссию компании? масштабируется? измерим KPI? имеет владельца? может быть автоматизирован? поддерживает AI? улучшает принятие решений? Если большинство ответов отрицательны, инициатива не переходит к реализации без дополнительного рассмотрения.

## Архитектурный вывод

Система KPI MainExperts — не набор независимых метрик, а единая модель бизнеса: каждый показатель связан с другими, каждое изменение распространяется по дереву зависимостей, каждый руководитель работает только со своим уровнем показателей. Собственник получает только стратегические KPI, детализация — через Drill Down по мере необходимости. KPI Philosophy формирует единый язык управления и обеспечивает сопоставимость данных между подразделениями, позволяя использовать AI, BI и управленческие процессы как элементы единой Management Operating System.

> Пробел: формулы конкретных KPI, числовые пороги (норма / предупреждение / критическое значение) и владельцы по каждому показателю в выданном срезе не приведены — раздел задаёт структуру паспорта, но не его заполнение.
