## Назначение

Operations Dashboard — центральное рабочее пространство COO и операционной команды MainExperts. Задача борда — обеспечить полную прозрачность исполнения услуг, загрузки экспертной сети, эффективности внутренних процессов и использования производственных мощностей компании. Борд является связующим звеном между продажами, экспертной сетью, AI и финансовой моделью.

Главный вопрос, на который отвечает борд:

1. Способна ли компания выполнить существующий и прогнозируемый спрос без потери качества обслуживания?

Основные задачи борда (п. 8.3): контроль Capacity; отслеживание загрузки экспертов; управление очередями клиентов; контроль SLA; прогноз нехватки ресурсов; обнаружение операционных ограничений; оценка эффективности процессов.

Основные пользователи: COO, Head of Operations, Head of Expert Network. Дополнительные: Owner, CEO, Product Owners.

## Структура экрана

Борд скомпонован по зонам сверху вниз (ASCII-схема источника, п. 8.4):

| Зона | Содержание |
|---|---|
| Operations Summary | Агрегированные показатели |
| Capacity · Utilization | Мощность · утилизация |
| Expert Network · Client Queue | Экспертная сеть · очередь клиентов |
| SLA · Workload Distribution | Контроль SLA · распределение нагрузки |
| Forecast · AI Capacity | Прогноз · мощность AI |
| Operational Alerts | Автоматические предупреждения |

## KPI-карточки

Верхний блок (Operations Summary) отображает агрегированные показатели (п. 8.5).

| KPI | Что показывает | Формат/единица | Порог/статус |
|---|---|---|---|
| Total Capacity | Общая доступная мощность | — | — |
| Used Capacity | Используемая мощность | — | — |
| Capacity Utilization | Утилизация мощности | — | — |
| Active Experts | Активные эксперты | — | — |
| Active Clients | Активные клиенты | — | — |
| Queue Length | Размер очереди | — | — |
| SLA Compliance | Выполнение SLA | — | — |
| Average Delivery Time | Среднее время оказания услуги | — | — |

> Оговорка: единицы измерения и пороги в источнике для карточек Summary не заданы (только название и описание).

Каждая карточка отображает: текущее значение; динамику; план; отклонение; прогноз. Единый каркас карточки (значение, план, отклонение, тренд, цвет статуса, Drill Down, AI Explain, история) — см. [00-framework](00-framework.md).

## Capacity Management

Capacity — одно из ключевых ограничений роста бизнеса (п. 8.6). Борд отображает: общую доступную мощность; используемую мощность; свободную мощность; прогноз загрузки; плановую мощность.

Дополнительно рассчитываются: Peak Capacity; Reserve Capacity; Critical Capacity.

### Capacity Breakdown

Мощность анализируется по нескольким измерениям, что позволяет быстро определить узкие места (п. 8.7): по продукту; по эксперту; по стране; по специализации; по языку; по типу услуги.

## Utilization

Для каждого эксперта рассчитывается коэффициент использования (п. 8.8).

Формула:

```
Utilization = Booked Hours / Available Hours
```

Статусы:

| Диапазон | Статус |
|---|---|
| Менее 50% | Недозагрузка |
| 50–85% | Оптимальная загрузка |
| 85–95% | Высокая загрузка |
| Более 95% | Критическая перегрузка — автоматически создаётся Alert |

## Expert Network

Каждый эксперт отображается отдельной карточкой (п. 8.9). Показываются: рейтинг; текущая загрузка; свободное время; количество клиентов; Contribution; отмены; NPS; AI Score. Карточки сортируются по текущей доступности.

## Client Queue

Борд отображает очередь клиентов (п. 8.10). Основные показатели: количество ожидающих; среднее время ожидания; максимальное ожидание; распределение по продуктам; распределение по экспертам.

Если ожидание превышает SLA, формируется Alert.

## SLA Dashboard

Для каждого продукта задаётся собственный SLA (п. 8.11). Контролируются: время первого ответа; время назначения эксперта; время начала услуги; время завершения; процент выполнения SLA. Нарушения выделяются автоматически.

## Workload Distribution

Показывает распределение нагрузки (п. 8.12). Цель — избежать ситуации, когда часть экспертов перегружена, а часть простаивает. Поддерживаются: тепловая карта; график загрузки; матрица распределения.

## Forecast

Прогнозируются (п. 8.13): Capacity; Queue; Hiring Demand; Client Growth; Expert Shortage. Все прогнозы рассчитываются автоматически.

### Hiring Forecast

Если прогноз показывает нехватку мощности, система автоматически рассчитывает (п. 8.14): количество необходимых экспертов; требуемые компетенции; страны; языки; ожидаемую дату найма; стоимость расширения команды.

## AI Capacity

Отдельно отображается мощность AI (п. 8.15). Основные показатели: Requests; Concurrent Sessions; Latency; Queue; GPU Utilization; Cost; Failure Rate. Таким образом Operations рассматривает AI как полноценный производственный ресурс.

## Drill-down

Любой показатель раскрывается до уровня первичного события (п. 8.18).

```
Capacity
  ↓ Country
  ↓ Specialization
  ↓ Expert
  ↓ Calendar
  ↓ Booking
```

```
Queue
  ↓ Product
  ↓ Country
  ↓ Client
  ↓ Request
```

## Alerts → Playbook

Автоматически создаются предупреждения (п. 8.16). Примеры:

- Capacity >95%.
- Queue превышает допустимый уровень.
- Нарушение SLA.
- Недостаток экспертов.
- Высокий процент отмен.
- Перегрузка AI.

> Пробел: в исходнике сортировка/ранжирование Alerts по критичности не задана.

Каждый Alert связан с соответствующим Playbook — см. [03-decision-loop](03-decision-loop.md).

## AI Copilot / AI Explain

AI помогает COO (п. 8.17). Примеры запросов: какие эксперты перегружены? где возникло ограничение роста? кого необходимо нанять? какие продукты не хватает мощности обслуживать? что станет следующим ограничением бизнеса? Ответ сопровождается ссылками на соответствующие KPI.

Граница: AI не утверждает решения и не меняет KPI (общий принцип — см. [00-framework](00-framework.md)).

## Фильтры

Поддерживаемые фильтры (п. 8.19): период; страна; эксперт; язык; специализация; продукт; тип клиента. Все элементы Dashboard синхронно обновляются.

## Производительность

| Функция | Требование |
|---|---|
| Dashboard | ≤2 сек |
| Capacity Forecast | ≤5 сек |
| Drill Down | ≤1 сек |
| AI Explain | ≤5 сек |

## Критерии приёмки

Operations Dashboard считается реализованным, если (п. 8.21):

- автоматически рассчитывается Capacity;
- отображается Utilization;
- отображается очередь клиентов;
- контролируется SLA;
- работает прогноз мощности;
- автоматически создаются Alerts;
- поддерживается Drill Down;
- AI формирует рекомендации;
- соблюдены требования производительности.
