## Назначение

Документ задаёт модель управления доступом MainExperts Management System. Система использует Role Based Access Control (RBAC): каждый пользователь имеет одну или несколько ролей, доступ определяется ролью, а права — на уровне объектов системы. Все операции журналируются.

## Роли

Основные роли и их полномочия по источнику.

| Роль | Полномочия (из источника) |
|------|---------------------------|
| Owner | Полный доступ: все борды, все KPI, все прогнозы (Forecast), все настройки. |
| CEO | Все управленческие функции; без изменения системных настроек. |
| CFO | Финансы, бюджет, Runway, Cash, Forecast. |
| COO | Эксперты, Capacity, Operations. |
| CMO | Маркетинг, продажи, продукты. |
| CTO | AI, инфраструктура, интеграции, мониторинг. |
| Product Owner | Только собственные продукты. |
| Expert | Только собственная аналитика. |
| Analyst | Просмотр данных; без изменения конфигурации. |
| Support | Техническая поддержка. |

## Матрица доступа

Каждый объект имеет права. Уровни прав: Read, Write, Admin. По источнику отмечены следующие права (✔ — отмечено в исходной матрице).

| Объект | Read | Write | Admin |
|--------|:----:|:-----:|:-----:|
| Dashboard | ✔ | — | — |
| KPI | ✔ | — | — |
| Forecast | ✔ | — | — |
| Alerts | ✔ | ✔ | — |
| Users | — | — | ✔ |
| Roles | — | — | ✔ |
| AI Settings | — | — | ✔ |

> Оговорка: в источнике матрица дана как набор отметок по объектам без явной привязки каждой ячейки к ролям; сопоставление «какая роль получает Read/Write/Admin на объект» в исходной таблице не раскрыто (см. Пробел ниже).

Все операции журналируются.

## Авторизация

Поддерживаемые способы входа:

- Email + Password;
- Google OAuth;
- Microsoft OAuth;
- SSO (SAML/OIDC);
- двухфакторная аутентификация.

## Сессии

Система должна поддерживать:

- ограничение времени жизни сессии;
- отзыв токенов;
- завершение всех активных сессий;
- обнаружение подозрительной активности.

> Пробел: конкретные значения (время жизни сессии, пороги обнаружения подозрительной активности, политика паролей и 2FA) в исходнике не раскрыты.

## Ответственность за объекты (Object Ownership)

Каждый объект управления имеет владельца. Запрещается наличие KPI без ответственного лица (Том I, Глава 4.5).

| Объект | Владелец |
|--------|----------|
| Revenue | Commercial Director |
| Contribution | CFO |
| Capacity | COO |
| Expert Quality | Head of Expert Network |
| AI Cost | CTO |
| Runway | CEO |

> Оговорка: ownership Revenue здесь закреплён за Commercial Director (Гл. 4.5); ниже, в матрице решений по изменению бюджета и связанным сценариям, владельцы решений отличаются — см. раздел «Ответственность за решения» и Расхождения.

## Ответственность за решения (Decision Ownership)

Решение всегда принадлежит одному владельцу; коллективная ответственность не допускается (Том I, Глава 8.6).

| Решение | Ответственный |
|---------|---------------|
| Изменение бюджета | CMO |
| Найм экспертов | COO |
| Изменение цены | Product Owner |
| Финансовые ограничения | CFO |
| Стратегические изменения | CEO |
