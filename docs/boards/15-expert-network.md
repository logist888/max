# 15. Борд: Экспертная сеть (Expert Network Dashboard)

> Источник: MainExperts Management System (MMS), Том II, Глава 9 «Expert Network Dashboard»; снимок 27.06.2026;
> Google Drive / MainExperts (`1.pdf` Том I, `2.pdf` Том II; владелец agafonov.agency,
> загр. 27.06.2026). Рабочий контекст — перед клиентскими материалами перепроверять с источником.

**Уровень:** L1 · **Владелец:** Head of Expert Network · **Доступ (просмотр):** COO, Quality Manager, Owner, CEO, Product Owners

## Назначение

Expert Network Dashboard — основной инструмент управления экспертной сетью MainExperts. Если Operations Dashboard отвечает на вопрос «Хватит ли компании мощности?», то Expert Network Dashboard отвечает на вопрос «Насколько эффективна сама экспертная сеть?». Главная задача борда — обеспечить развитие экспертной экосистемы без потери качества обслуживания клиентов (п. 9.1).

Борд должен позволять (п. 9.1):

1. управлять качеством экспертов;
2. контролировать загрузку;
3. оценивать эффективность;
4. выявлять лучших специалистов;
5. обнаруживать зоны риска;
6. прогнозировать развитие экспертной сети.

Основные пользователи — Head of Expert Network, COO, Quality Manager. Дополнительные — Owner, CEO, Product Owners (п. 9.2).

## Структура экрана

Зоны борда сверху вниз (ASCII-схема источника, п. 9.3):

| Зона | Содержимое |
| --- | --- |
| Expert Summary | Агрегированная информация по экспертной сети |
| Capacity · Quality | Загрузка сети; качество экспертов |
| Performance · Revenue | Эффективность экспертов; выручка |
| Ratings · Client Satisfaction | Рейтинги; удовлетворённость клиентов |
| Development · Forecast | Развитие экспертов; прогноз |
| Expert Alerts | Автоматические предупреждения |

## KPI-карточки

Верхний блок Expert Summary содержит агрегированную информацию по экспертной сети (п. 9.4).

| KPI | Что показывает | Формат/единица | Порог/статус |
| --- | --- | --- | --- |
| Active Experts | Активные эксперты | — | — |
| Available Capacity | Доступная мощность | — | — |
| Average Utilization | Средняя загрузка | — | — |
| Average Rating | Средний рейтинг | — | — |
| Active Clients | Активные клиенты | — | — |
| Average NPS | Средний NPS | — | — |
| Contribution | Contribution экспертной сети | — | — |
| Revenue | Общая выручка | — | — |

Все показатели отображаются относительно прошлого периода, относительно плана и относительно целевых значений (п. 9.4). Единый каркас KPI-карточки — см. [00-framework](00-framework.md).

> Пробел: единиц измерения, форматов и порогов/статусов KPI в источнике нет.

## Карточка эксперта

Каждый эксперт имеет собственную карточку (п. 9.5):

| Группа | Поля |
| --- | --- |
| Общая информация | ФИО, статус, специализация, языки, страна, дата начала работы |
| Производительность | Revenue, Contribution, количество клиентов, консультации, средний чек |
| Качество | Rating, NPS, жалобы, отмены, повторные консультации |
| Нагрузка | Capacity, Utilization, свободные часы, планируемая загрузка |
| AI | AI Assistance Rate, использование AI, экономия времени |

## Expert Performance

Для каждого эксперта рассчитывается интегральная оценка — Expert Performance Score (п. 9.6). В расчёт входят: Revenue, Contribution, NPS, Rating, Repeat Clients, Utilization, SLA, AI Adoption.

> Пробел: формула/веса Expert Performance Score в источнике не приведены.

## Expert Rating

Рейтинг строится на нескольких источниках; вес каждого источника задаётся системой (п. 9.7). Пример распределения весов:

| Источник | Вес |
| --- | --- |
| Клиенты | 40% |
| Повторные покупки | 20% |
| SLA | 15% |
| Внутренний аудит | 15% |
| AI Quality Score | 10% |

Рейтинг автоматически пересчитывается после каждого завершённого проекта (п. 9.7).

> Оговорка: веса даны как пример («Например»), а не как зафиксированная конфигурация.

## Client Satisfaction

Контролируются (п. 9.8): NPS, CSAT, повторные обращения, жалобы, возвраты, рекомендации. Все показатели доступны как по отдельному эксперту, так и по всей сети.

## Revenue Analysis

Доход анализируется одновременно по нескольким измерениям (п. 9.9): по эксперту, продукту, стране, языку, категории клиентов, типу услуги. Борд показывает не только Revenue, но и Contribution каждого эксперта.

## Capacity Management

Каждый эксперт имеет календарь доступности (п. 9.10). Система отображает: свободные окна, будущую загрузку, прогноз перегрузки, прогноз простоя. При достижении пороговых значений создаётся Alert.

> Пробел: конкретные пороговые значения для Alert в источнике не указаны.

## Development Dashboard

Каждый эксперт имеет индивидуальный план развития (п. 9.11). Контролируются: завершённые обучения, сертификации, внутренние экзамены, рекомендации AI, освоенные продукты, новые компетенции. Рост квалификации рассматривается как стратегическая инвестиция компании.

## Expert Forecast

Система автоматически прогнозирует (п. 9.12): будущую загрузку, ожидаемый Revenue, Contribution, вероятность ухода, риск выгорания, необходимость обучения. Все прогнозы сопровождаются уровнем уверенности модели.

## Матрица эффективности

Борд автоматически распределяет экспертов по квадрантам в осях «качество × Revenue» (п. 9.16):

```
              Высокое качество
                     │
   (не подписан)     │     ★ Stars
 Low Revenue ────────┼──────── High Revenue
   Improvement       │     Revenue Risk
                     │
              Низкое качество
```

> Пробел: в извлечении PDF строка подписей квадрантов линеаризована; источник даёт три метки — ★ Stars (высокое качество), Improvement и Revenue Risk (низкое качество). Четвёртый квадрант (высокое качество, низкая выручка) в источнике не подписан; метки не достраивались, раскладка — по осям.

Так руководитель сразу видит: лучших экспертов, кандидатов на развитие, потенциальные риски, перегруженных специалистов (п. 9.16).

## Drill-down

Любой показатель раскрывается; все уровни доступны без потери контекста (п. 9.15).

```
Contribution
  ↓ Expert
  ↓ Client
  ↓ Consultation
  ↓ Invoice
  ↓ Payment
```

```
Rating
  ↓ Survey
  ↓ Client
  ↓ Session
  ↓ Feedback
```

## Alerts → Playbook

Автоматически создаются предупреждения (п. 9.14). Примеры:

- Utilization >95%;
- Rating снизился;
- рост жалоб;
- падение NPS;
- отсутствие новых клиентов;
- высокая вероятность увольнения.

Каждый Alert имеет владельца, приоритет, Playbook и рекомендуемые действия. Связка Alert → Playbook — см. [03-decision-loop](03-decision-loop.md).

## AI Copilot / AI Explain

AI Expert Copilot помогает руководителю экспертной сети (п. 9.13). Примеры запросов:

- Какие эксперты готовы принять новых клиентов?
- Кто перегружен?
- Кто показывает лучший рост?
- Кого необходимо обучить?
- Какие специалисты находятся в зоне риска ухода?

AI объясняет рекомендации ссылками на KPI и историю изменений. Граница роли AI — он объясняет, прогнозирует и рекомендует, но не утверждает решения и не меняет KPI (общий принцип — см. [00-framework](00-framework.md)).

## Фильтры

Поддерживаются фильтры (п. 9.17): период, страна, язык, специализация, продукт, статус, уровень эксперта, тип клиента. Все визуализации обновляются синхронно.

## Производительность

Требования (п. 9.18):

| Функция | Требование |
| --- | --- |
| Загрузка Dashboard | ≤2 сек |
| Expert Card | ≤1 сек |
| Drill Down | ≤1 сек |
| Forecast | ≤5 сек |
| AI Explain | ≤5 сек |

## Критерии приёмки

Expert Network Dashboard считается реализованным, если (п. 9.19):

- отображаются все активные эксперты;
- автоматически рассчитывается Performance Score;
- рассчитывается Rating;
- отображается Capacity;
- строится прогноз нагрузки;
- AI формирует рекомендации;
- автоматически создаются Expert Alerts;
- поддерживается Drill Down;
- соблюдены требования производительности.
