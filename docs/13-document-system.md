# 13. Система корпоративной документации (DMS)

> Снимок 12.07.2026. Авторская архитектурная разработка (Claude Code) по запросу основателя:
> спроектировать систему корпоративной документации уровня Enterprise для MainExperts.
> Опора (по приоритету): ISO 9001 · BPM CBOK · PMBOK · BABOK · TOGAF · ITIL · COBIT · Agile/Scrum ·
> практики Google/Atlassian/Stripe/GitLab/Notion/Linear · функциональная модель Divisions 1–7
> (адм. технология Хаббарда — **только как орг-каркас деления на семь подразделений**; практики —
> современные; при конфликте побеждает современный менеджмент). Это рабочий каркас, не выверенный
> источник: перед клиентскими материалами факты перепроверяются с источником и датой.

Этот файл — точка входа в модуль. Детальный канон — в `dms/`. DMS проектирует **систему
управления документами** (какие артефакты существуют, кто владеет, как живут, как связаны),
надстраиваясь над уже существующим каноном: система бордов MMS (`08-board-system.md`) управляет
**решениями**, модель данных (`10-data-model.md`) управляет **данными**, DMS управляет
**документами**. Три контура, один язык уровней L0–L3 и один словарь владельцев.

## Что это

Полный проект корпоративной документации: от бизнес-архитектуры (Компания → Divisions →
Функции → Процессы → Роли → Ответственность → Документы → Системы → Отчёты → Метрики) до
реестра из 152 документов с карточками, матрицами, деревьями, роадмапом и governance-слоями
(Data + AI). Функциональный каркас — современная адаптация семи подразделений; наполнение —
международные практики Приоритетов 1–2.

## Тома модуля (порядок разделов)

- `dms/01-divisions.md` — раздел 2: адаптация Divisions 1–7 (назначение/функции/процессы/роли/
  ответственность/взаимодействие) + мэппинг на 7 бордов MMS.
- `dms/02-process-map.md` — раздел 3: 12 процессов P01–P12, подпроцессы, связь с документами.

**Том II — Классификация и реестр (разделы 4–6).**
- `dms/03-classification.md` — раздел 4: **единый словарь терминов** (21 класс + 2 расширения),
  три оси (класс/категория/Division), ЖЦ (9 этапов), зрелость (MVP/Growth/Scale/Enterprise),

- `dms/07-trees.md` — раздел 11: дерево наследования + дерево зависимостей (с блокерами).

**Том IV — Внедрение и governance (разделы 12–16).**

## Ключевые проектные решения (и почему так)

1. **Класс ≠ категория ≠ Division.** Три независимые оси. «Финансовые/HR/AI-документы» запроса —
   это *категории* (домены), а не классы; иначе неизбежны дубликаты (нарушение «не смешивать»).
2. **Лестница обязательности без пересечений.** Регламент (много функций) → Процедура (одна
   функция) → SOP (одна операция роли) → Инструкция (шаг в инструменте). Один непересекающийся
   уровень охвата на класс.
3. **Divisions ≠ борды один-к-одному.** Семь бордов MMS функциональны, семь Divisions
   орг-структурны; расхождения (Operations распределён по D4/D5; нет отдельного борда D1)
   зафиксированы, не спрятаны.
4. **Governance надстраивается, не дублирует.** Data Dictionary/словарь метрик уже частично есть
   в `10-data-model.md`; DMS добавляет владение, роли, качество, lineage — которых там нет.
5. **Полнота реестра — карта, а не бэклог.** На запуск исполняется только Must×Critical Этапа 1;
   остальное — по мере зрелости (перенос принципа «стандарт без масштаба не работает»).

## Критический разбор (роль критика, не соглашателя)

1. **Главный риск — разрыв амбиции и стадии.** Enterprise-DMS на 152 документа против компании,
   готовящей первый вебинар командой ≤8. Тот же разрыв, что у MMS (`08-board-system.md`). Ответ
   DMS — роадмап: на MVP лишь ~47 документов ядра Этапа 1 (законность + достоверность + измеримость),
   остальное отложено по триггерам. Строить полный набор сейчас — против V4.1.
2. **Два жёстких блокера держат всё.** Методология скрининга (`D5-SPC-01`, блокер №1) держит
   продуктовую цепочку; compliance-gate (`D1-POL-03` + `D1-CHK-02`) держит запуск трафика. Ни
   документ, ни дашборд их не обходят — это зависимости, не рекомендации.
3. **Оценки — авторские, не факт.** MoSCoW/критичность/зрелость/трудоёмкость — `[оценка]` для
   стадии 07.2026. Владельцы — целевая оргструктура; сейчас роли совмещены в основателе и узком
   круге (та же оговорка, что у бордов).
4. **Три расхождения канона не разрешены** (владелец Revenue; префикс `KPI-`/`KPI_`; состав
   Strategic KPI) — с указанием места разрешения, но это решение основателя.
5. **DMS не переспроектирует Operations-борд** (узкое место снято автоматизацией) — смежная
   задача канона, вне скоупа.

**Вывод.** Ценность DMS сейчас — единый язык и целевая карта системы документации, к которой
идут по мере появления данных и людей, плюс исполнимый набор Этапа 1, снимающий три зашитых
противоречия цели $1M. Не немедленный бэклог на 152 документа.
