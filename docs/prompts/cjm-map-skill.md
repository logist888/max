# Промпт: скилл «карта CJM в SVG» для передачи разработчикам

> Назначение: исполнимый промпт. Скармливается Claude Code в репозитории. На выходе —
> самодостаточный скилл `.claude/skills/cjm-map/`, который по файлу данных собирает карту
> пути клиента: блок-схема с дорожками и шагами, под ней столбцы-стикеры CJM в тех же
> колонках. Образец результата — `vault/40-reports/2026-11-03-cjm-poisk-vse-napravleniya-shema-i-stikery.svg`
> и `docs/html/cjm-poisk-vse-napravleniya.html`. Язык артефактов — русский.

---

## РОЛЬ И ЦЕЛЬ

Ты — инженер, который превращает одноразовый скрипт в продукт для чужой команды. Нужно
сделать скилл, который разработчик MainExperts (или внешний подрядчик) запускает сам: кладёт
файл с описанием пути, получает карту в SVG без правки кода и без доступа к этой сессии.

Критерий успеха: разработчик, не видевший этот чат, на чистом клоне репозитория за один
вызов получает карту, визуально эквивалентную образцу, по новому файлу данных.

## ЧТО ЕСТЬ СЕЙЧАС (проверь сам, не верь пересказу)

1. Генератор карты существует только как набор скриптов вне репозитория (рабочая папка
   сессии): `build_flow.py` (блок-схема), `build_stream.py` (сборка потока: схема сверху,
   стикеры снизу в тех же колонках), `build_board2.py` и `build_unified.py` (данные и лента),
   `svg_make.py` / `svg_make2.py` (экспорт в SVG), `svg_export.js` (снимок страницы через
   Playwright), `shot_stream.js`. Если файлов нет в рабочей папке, восстанови логику из
   образца: `docs/html/cjm-poisk-vse-napravleniya.html` содержит данные и разметку, SVG-файлы
   в `vault/40-reports/` — эталон результата.
2. Данные пути зашиты прямо в Python-код (списки действий, связей, стикеров по блокам 1–10),
   пути к рабочей папке прописаны абсолютно. Скилл в таком виде передать нельзя.
3. Две выдачи SVG: с текстом в `<text>` (`...-text.svg`) и «безопасная» без `<text>`, где
   надписи переведены в контуры шрифта Inter, наконечники стрелок — полигоны (нужна, чтобы
   карта одинаково открывалась в Figma, Illustrator, Miro и на телефоне). Обе нужны.

## ЧТО СДЕЛАТЬ

### 1. Формат входных данных (главная работа)

Вынеси данные из кода в один файл `journey.yaml` (или JSON; выбери YAML, если не нужна
дополнительная зависимость, и обоснуй выбор в README одной строкой). Схема, которую должен
понимать генератор:

- `meta`: название карты, дата, версия, источник, язык.
- `lanes`: дорожки блок-схемы (роль или система: клиент, портал, консультант и т. п.) —
  идентификатор, подпись, цвет.
- `blocks`: этапы пути (в образце блоки 1–10), у каждого: номер, название, диапазон
  колонок, дорожка.
- `steps`: шаги блок-схемы — идентификатор, блок, дорожка, колонка, тип (`action` — действие,
  `decision` — развилка, `exit` — выход/потеря клиента, `system` — действие системы),
  текст.
- `links`: связи между шагами — откуда, куда, подпись на стрелке, флаг `loss` (красная
  стрелка выхода).
- `columns`: столбцы CJM под схемой — для каждого блока набор строк-стикеров (в образце:
  действия, мысли, эмоции, боли, точки контакта, возможности; точный состав возьми из
  образца и закрепи в схеме как перечисляемый словарь `rows`).
- `screens` (необязательно): строка «Экраны» внизу — ссылки на снимки интерфейса по блокам.

Обязательно: схема валидации (JSON Schema или проверки в коде) с понятными сообщениями об
ошибках: неизвестная дорожка, шаг без блока, связь на несуществующий шаг, пустой текст,
текст длиннее допустимого для стикера. Валидация запускается до отрисовки.

### 2. Генератор

- Один вход: `python scripts/cjm_map/build.py journey.yaml --out out/` (или эквивалент).
  Никаких абсолютных путей; всё относительно корня репозитория или аргументов.
- Раскладка: колонки задают ось времени слева направо; блок-схема и стикеры блока стоят в
  одних и тех же колонках; ширина колонки подстраивается под самый длинный текст, перенос
  строк считается по метрикам шрифта, а не по числу символов.
- Блок-схема: дорожки, шаги, ромбы развилок, красные стрелки потерь, стрелки с изломами без
  пересечения шагов (если пересечение неизбежно, отметь его в отчёте).
- Столбцы CJM: цветная шапка блока с номером, ряды стикеров с подписью ряда слева.
- Выход: `map.svg` (контуры, без `<text>`, без маркеров, фильтров и вложенных `<svg>`),
  `map-text.svg` (с `<text>`, текст выделяется и ищется), `map.png` и `map-8000px.png`,
  `map.pdf`, `map.html` (интерактивная версия с масштабированием, если есть в образце).
- Шрифт: Inter из системных шрифтов; если шрифта нет, скилл сам сообщает, как установить, и
  не падает с трассировкой. Кириллица обязательна.
- Детерминизм: один вход даёт побайтно один и тот же SVG (без случайных идентификаторов и
  временных меток в теле файла).

### 3. Скилл

Каталог `.claude/skills/cjm-map/`:

- `SKILL.md` — по формату остальных скиллов репозитория (см. `.claude/skills/report/SKILL.md`):
  когда вызывать, входы, шаги, проверка результата, чего не делать. Короткий, в
  повелительном наклонении.
- `scripts/` — генератор и зависимости, `requirements.txt` с точными версиями (fontTools,
  PyYAML и т.д.), инструкция по установке одной командой.
- `examples/` — `journey.example.yaml` (полный пример из образца, 10 блоков) и
  `journey.minimal.yaml` (три блока, для быстрого старта), результат их сборки.
- `README.md` — на русском, для разработчика: что получится, как запустить за 5 минут, как
  добавить блок, шаг, дорожку, строку CJM; как читать сообщения валидатора; как открыть SVG
  в Figma и Miro; ограничения.

### 4. Проверка (обязательна, показать результаты)

1. Собери карту из `examples/journey.example.yaml` и сравни с эталонным SVG из
   `vault/40-reports/`: число блоков, шагов, связей, стикеров совпадает; разошедшееся
   перечисли. Допустимое расхождение — только в мелочах раскладки, не в содержании.
2. Собери карту из `journey.minimal.yaml` на чистом клоне (отдельная папка, без рабочих
   файлов сессии): сборка проходит.
3. Сломай данные тремя способами (неизвестная дорожка, битая связь, пустой текст): валидатор
   останавливает сборку и называет строку и поле.
4. Проверь `map.svg` Playwright-снимком и глазами: надписи читаются, нет налезаний, стрелки
   не пересекают шаги. Проверь, что в файле нет `<text>`, `<marker>`, `<filter>`, `<foreignObject>`
   и вложенных `<svg>`.
5. Запусти сборку дважды и сравни хеши: совпадают.

## ОГРАНИЧЕНИЯ

- Не меняй существующие карты и документы канона. Скилл — отдельный каталог и отдельный
  каталог скриптов.
- BFAS, Big Five и RIASEC в примерах не называть: только рабочие названия. Данные потока 1
  (HNW) в примеры не включать.
- Пример данных — только публичная часть пути (поток 2). Персональных данных клиентов нет.
- Не выдумывай: где в образце нет сведений о составе рядов CJM, возьми состав из самого
  образца и пометь пробел, а не придумывай ряды.
- Зависимости только открытые и без сетевых вызовов во время сборки.
