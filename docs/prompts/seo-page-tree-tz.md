## Ограничения

- **Не копировать контент и данные Booking, Skyscanner, Aviasales.** Их страницы — образец состава блоков и логики, не источник данных. Копирование текстов, цен, отзывов, изображений нарушает условия сервисов и авторские права. Допустимые источники: база портала; официальные партнёрские API и фиды по договору; открытые данные с лицензией и атрибуцией (OpenStreetMap, Wikidata, GeoNames и подобные). Для каждого блока в ТЗ указать источник, лицензию, периодичность обновления, дату последней сверки.
- **Не обещать индексацию.** Число страниц в sitemap не равно числу страниц в индексе; у Aviasales в Google в 6 раз больше страниц, чем в sitemap, у Booking доля индексируемого неизвестна. Все оценки — «потолок» или «ставка», с условием, при котором они перестанут быть верными.
- **Риск «массового малоценного контента».** Поисковики наказывают массовую генерацию страниц без собственной ценности. ТЗ обязано дать для каждого типа страницы порог включения в индекс по наполненности и спросу, правило тонкой страницы (что делать, если данных мало: `noindex`, canonical на родителя, не создавать) и порядок снятия страниц с индекса.
- **Данные несовершеннолетних.** Лайки и сравнения пользователей — поведенческие данные подростков 10–18 лет. Публичные страницы не раскрывают выбор конкретного человека; наборы строятся только из агрегата не менее N независимых пользователей (N — параметр, умолчание предложить и обосновать); защита от накрутки обязательна.
- Правило данных CLAUDE.md: каждый факт — источник, дата, ссылка. Профессии — O*NET и ESCO; рынок труда РФ — api.hh.ru; MENA — источники фрагментированы, пометить пробелом.
- Названия тестов BFAS/Big Five и RIASEC в публичных страницах не использовать (нет лицензии); в дереве Сергея «Тип работы» хранит коды RIASEC — это внутренние значения, в адресах и текстах нужны рабочие названия.
- Не смешивать поток 1 и поток 2; страницы относятся к потоку 2 (воронка).
- Центральная гипотеза скрининга не валидирована; на ней не строить требования.
- Сжатие важнее объёма: ТЗ читается разработчиком за 40 минут; детали — в таблицах и приложениях.

## Критерии качества

1. **Полнота дерева.** Для каждого типа страницы: шаблон адреса, обязательные сущности и фасеты, условие создания, условие индексации, canonical, блоки, источник каждого блока, пустое состояние.
2. **Подсчёт.** Для каждого типа — формула числа страниц, параметры, пример расчёта на известных числах (с пометкой источника), воронка «возможных → создаваемых → попадающих в sitemap → ожидаемо индексируемых» с долями как гипотезами.
3. **Прослеживаемость.** У каждого требования — источник (вход, бенчмарк, дерево Сергея, указание владельца с датой) или «предложение».
4. **Проверяемость.** Каждое требование принимается тестом или осмотром.
5. **Честность.** Противоречия входов (прежний `02-pseo.md`, решения владельца, ограничения поисковиков и лицензий) показаны таблицей.
6. **Пригодность для разработчика.** Нет требования, которое можно понять двояко; для каждого параметра одно умолчание.

## Порядок выполнения

1. **Сверка входов.** Составить таблицу «утверждение → источник → противоречие с другим источником → вердикт». Обязательно: решения владельца против `seo-platform/02-pseo.md` (индексация сравнений, массовая генерация фасетов, пороги «≥ 2 вузов»); дерево Сергея против концепта (короткие программы); «возьмём из букинг-сервисов» против лицензий.
2. **Грамматика страниц.** Описать, из чего собирается любая страница: `шаблон = тип + слоты сущностей + слоты фасетов + слоты геопривязки`. Перечислить типы и их слоты. Отдельно — три состояния существования страницы: материализована (данные есть), оболочка (данных мало: показаны блоки по соседним сущностям и форма «подобрать»), не создаётся (404 или перенаправление).
3. **Дерево и подсчёт.** Построить дерево типов (диаграмма Mermaid и таблица). Для каждого типа дать формулу объёма и пороги. Минимальный набор типов, который нужно рассмотреть:
   - справочные: страна, город, вуз, колледж, школа, программа, направление, сфера, профессия, олимпиада, короткая программа;
   - комбинации: «направление × страна», «направление × город», «уровень × страна», «язык × страна», «форма × город», «бюджет до X × страна», «профессия → где учиться», «короткие программы: тема × страна × период × возраст»;
   - маршруты в смысле Авиасейлса: «откуда → куда» для образования («из Казахстана в Германию: IT-бакалавриат»), страница-оболочка с формой;
   - сравнения (раздел ниже), геострaницы (раздел ниже), подборки и топы.
   Пороги (минимальное число программ, минимальный набор блоков с данными, минимальная длина уникального текста) — параметры; предложить значения и объяснить, как их подбирать по показам.
4. **Сравнения.** Описать три вида: (а) пара «A или B» для вузов, программ, стран, городов; (б) наборы 3–5 по фильтрам совпадения (бюджет, город, страна, направление, язык, форма), включая наборы из разных городов и стран; (в) подборки из агрегата выбора пользователей. Для каждого: правило отбора кандидатов (ближайшие по профилю, не все сочетания: число пар растёт как n²), канонический порядок идентификаторов в адресе, ограничение числа страниц, порог спроса, обязательные уникальные блоки (таблица сравнения параметров, «кому подходит», разница цены, срока, языка, срока подачи), правило индексации, защита от тонкого содержания, защита приватности и накрутки.
5. **Геопривязка.** Описать сущности: достопримечательность, улица или район, природный регион (полигон, например «Альпы»), город; отношение «рядом» (расстояние до учреждения в метрах и способ перемещения; радиус — параметр по типу объекта); источники координат и названий на нескольких языках; ранжирование объектов по известности; минимальное число учреждений в радиусе для создания страницы; правила против дублей со страницами города и района. Это вторая очередь: в ТЗ описать модель данных и правила сейчас, генерацию — по этапам.
6. **Наполнение блоками.** Составить каталог блоков из бенчмарка (показатели, витрина предложений, динамика цен и сроков, FAQ с микроразметкой, редакционный текст о месте, подборки, перелинковка на соседние сущности, статьи журнала, перелинковка на сравнения) и для каждого типа страницы указать: набор блоков, статика или динамика, источник данных, лицензия, обновление, пустое состояние, микроразметка. Особо описать **оболочку**: что видит посетитель и робот, когда результатов ещё нет (как у Авиасейлса до нажатия «подобрать»), и чем она полезна.
7. **Жизненный цикл и индексация.** Статусы страницы (создана, доступна, в sitemap, индексируется, снята), правила перехода между ними по метрикам (цикл «метрика → порог → действие» из `docs/12`), шардирование sitemap (до 50 000 URL на файл, индекс файлов), robots.txt (закрыть параметры, как у Skyscanner и Aviasales), canonical, hreflang, пагинация, перенаправления 301 и коды 404/410, страница-сирота, ограничение глубины. Показать, как устроено у конкурентов, и что взято.
8. **Агенты-помощники.** Запустить четыре независимых субагента с одинаковыми входами и разными ролями: (1) поисковая оптимизация и индексация; (2) данные, геоданные, лицензии и источники; (3) сравнения и пользовательские подборки, приватность, антифрод; (4) разработка: нагрузка, генерация, кэш, шардирование, пересборка. Каждый возвращает находки с источником, требования к ТЗ, риски и отдельно — «как этим злоупотребит или как это сломается». Агентам не сообщать авторство решений владельца.

## Внутренние проверки перед выдачей

- У каждого типа страницы есть: адрес, слоты, условие создания, условие индексации, canonical, блоки, источник каждого блока, пустое состояние.
- У каждого параметра (порог, радиус, N независимых пользователей, число страниц в sitemap-файле) одно умолчание, и все разделы написаны под него.
- Все оценки объёма с условием; нет слова «гарантия» без определения; миллиард страниц нигде не подан как факт.
- Для каждого блока указан источник и лицензия; нет блока, наполняемого копированием со страниц конкурентов.
- Противоречия с `seo-platform/02-pseo.md` вынесены таблицей, прежние документы не изменены.
- Сравнения: правило отбора не допускает n²-взрыва; адрес сравнения единственный для набора (канонический порядок); индексируются только страницы с порогом наполненности и спроса.
- Пользовательские выборы: публичные страницы не содержат идентификаторов, порог агрегата и защита от накрутки заданы; данные несовершеннолетних учтены (`docs/05`).
- Геопривязка: источники координат с лицензией и атрибуцией; правило против дублей с городом и районом.
- Короткие программы описаны (поля, фильтры, адреса, пороги), школы описаны как новая сущность.
- Есть таблица объёма: обязательно в первом выпуске / вручную / после; очерёдность по этапам (справочные, комбинации, сравнения, геопривязка).
- Есть таблица зависимостей от портала Сергея (какие поля и справочники нужны, чего нет, владелец, обход).

4. Грамматика страниц и дерево типов (диаграмма, таблица, адреса).
5. Подсчёт объёма: формулы, параметры `N_*`, запрос к базе, пример, воронка, пороги.
6. Каталог блоков и состав страниц по типам; оболочка; статика и динамика; источники и лицензии.
7. Сравнения: виды, отбор, адреса, уникальные блоки, индексация, приватность и антифрод.
8. Геопривязка: модель, отношение «рядом», источники, пороги, дубли, этапы.
9. Индексация и жизненный цикл: статусы, переходы, sitemap, robots.txt, canonical, hreflang, разметка, перенаправления, мониторинг.
10. Данные и интеграции: источники, лицензии, партнёрские API, задания пересборки, расписание.
11. Нагрузка и генерация: рендеринг, кэш, шардирование, лимиты, очереди, порядок пересборки.
12. Метрики и решения: «метрика → порог → действие», эксперименты, пересмотр порогов.
13. Объём первого выпуска и очерёдность по этапам; зависимости от портала Сергея.
14. Критерии приёмки: сквозные сценарии с ожидаемым результатом.
15. Открытые решения: владелец, срок, умолчание, цена ошибки.
16. Разбор красной команды: подтверждено / спорно / отклонено, что изменилось.
17. Проверка по правилам проекта.
