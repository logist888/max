Для разработчика портала (репозиторий `mainexperts-portal`) или для сессии Claude Code в нём. Версия 2 от 13.11.2026 (учтены решения ВЛ-10…ВЛ-13: режим контента, числа разрешены, «в» и «из» отдельно, происхождение × назначение). ## Цель

Для каждого типа страницы разложить все возможные страницы на пять непересекающихся классов и назвать причины, по которым страница не годится к индексу.

| Класс | Смысл | Что с адресом |
|---|---|---|
| **K1. В индекс** | пороги выполнены, данных и блоков достаточно | 200, `index`, в sitemap |
| **K2. После уникализации** | данных достаточно, не хватает того, что можно добавить: редакционный блок по фасету, FAQ, срок подачи, подборка | 200, `noindex`, потом K1 |
| **K3. Canonical на родителя** | состав совпадает с родителем (один вуз в городе, комбинация даёт тот же состав) | canonical вверх |
| **K4. Оболочка** | сущности есть, данных меньше порога | 200, `noindex` |
| **K5. Не создаётся** | нет сущности или нет программ | 404 |

Сумма K1…K5 равна «возможных». Для K2 по каждой причине дать два числа: страниц с этой причиной и страниц, которым не хватает **только** её.

## Параметры (три сценария: мягкий / базовый / жёсткий)

| Параметр | Мягкий | Базовый | Жёсткий |
|---|---|---|---|
| `P_inst` — вузов в комбинации | 2 | 2 | 3 |
| `P_prog` — программ (и одновременно ≥ `P_inst` вузов) | 2 | 3 | 5 |
| `P_short` — коротких программ (курсов) | 1 | 2 | 3 |
| `k_pair` — соседей для пар сравнения | 5 | 5 | 3 |
| `G_min` — вузов в радиусе геообъекта | 2 | 3 | 5 |
| `K_origin` — стран отправления, индексируемых в парах | 15 | 30 | 60 |

Главный вывод строится по базовому сценарию; два других дают вилку.

## Порядок работы

**Шаг 0. Разведка схемы.** Найти, где лежат: страна, город, регион, вуз, колледж, программа, направление, профессия, курс, языковая школа, календарь сроков, цены, курсы валют; **«нужна ли виза и какая» и «цены под своё гражданство и валюту»** (данные «гражданство × страна назначения»); справочники падежей и коротких имён, если есть. Источники: `crates/portal-search`, миграции, обработчики `filter`, `panels`, `places`. Если данные в поисковом индексе, а не в SQL, считать через индекс и написать, как. Не угадывать: чего не нашёл, записать в «Не найдено».

**Шаг 1. Сверка с матрицей.** Заполняемость по одному параметру известна из матрицы (`docs/25`): не пересчитывать. Проверить только расхождения (число направлений: матрица даёт 12, справочник базы может давать больше) и поля, которых в матрице нет: падежи (`name_prep`, `name_gen`, `name_to`), `lang_on`, `name_short`, возраст и даты курсов, школы K-12, координаты.

**Шаг 2. Совместное наличие** (то, чего матрица не показывает). Для типов ниже получить: `возможных`, `существует` (≥ 1 программа), `проходит порог` по трём сценариям.

| Тип | Что считать |
|---|---|
| T01 страна, T02 город | страны и города с ≥ 1 программой; одновузовые города отдельно |
| T03 вуз, T04 колледж | записи; из них с идентичностью (название, страна, город, тип, сайт) и ≥ 4 заполненными D1-блоками |
| T06 программа | программы с описанием; с ценой; с описанием и ценой одновременно; без описания (кандидаты на canonical вверх) |
| T07 направление, T08 сфера | с ≥ `P_prog` программ и ≥ `P_inst` вузов |
| T09 профессия | профессии с связанными направлениями; с собственным текстом |
| T11 курс | записи; с возрастом; с датами старта; с ценой; летние школы отдельно; с датой в будущем |
| T20 направление × страна | пары с ≥ `P_prog` и ≥ `P_inst` |
| T21 направление × город | пары с ≥ `P_inst` |
| T22 уровень × страна, T23 язык × страна, T24 форма × город | пары с порогом |
| T25 бюджет до X × страна | X = 1 000, 2 000, 5 000, 10 000, 20 000 USD в год |
| T26 профессия × страна | через направления профессии, с порогом |
| T27 короткие: тема × страна × месяц × возраст (10–13, 14–17) | комбинации с ≥ `P_short`; если коротких программ нет, 0 и причина |
| T31 страна отправления | страны отправления, у которых есть данные: виза; цены под гражданство; признание документов (если хранится) |
| T30 пара «из X в Y» (страна → страна) | пары, где у страны назначения есть программы и у пары есть собственные данные (виза или цена под гражданство); число пар по числу заполненных блоков (0, 1, ≥ 2) |
| T34 страна → город, T35 страна → вуз, T36 страна → программа | то же для уровня назначения; отдельно число стран отправления, проходящих `K_origin` по спросу (если данных о спросе нет, взять страны с наибольшим числом пар с данными) |
| T30c город отправления | есть ли в базе поля по городам отправления (визовые центры, консульства, перелёты); если нет, 0 и «нужно добавить поля» |
| T43 страница из фильтров | допустимые наборы `docs/22` R-4.3.3 (страна+направление; страна+уровень; страна+язык; +направление+уровень; +язык; +уровень+язык; +«бесплатно»; город+направление): по каждому набору число комбинаций, затем пороги; пары, совпадающие с T20–T26, не считать повторно; год набора: для каких лет есть даты набора или календарь страны |
| T40 пара «A или B» | `n`, `n·k_pair` для вузов и программ при `k_pair` 5 и 3; способ расчёта близости описать |
| T41 набор 3–5 | не считать; перечислить кураторские фильтры, если они есть |
| T50–T53 геостраницы | объекты и вузы с координатами; число пар «объект ↔ вуз» в радиусе 5 км при `G_min` = 3; если координат нет, 0 и причина |

**Шаг 3. Классы.** По каждому типу и для базового сценария: `возможных → K1 → K2 → K3 → K4 → K5`. Для типов режима контента (T30, T31, T34–T36, T43) K1 и K2 различаются **наличием редакционных блоков по фасету**, а не данными базы: считать K1 как «данные есть», K2 как «данных достаточно, редактор блоки ещё не написал»; отдельно — сколько редакционных блоков надо написать (страна назначения, страна отправления, уровень, язык, год, направление: по одному блоку на значение фасета, а не на каждую комбинацию).

**Шаг 4. Чувствительность.** Для T20, T21, T22, T23, T26 вывести число страниц при `P_prog` ∈ {1, 2, 3, 5, 10}.

**Шаг 5. Слепые зоны** (коротко):
1. Сколько страниц получит `noindex` из-за отсутствия цены, срока подачи или текста.
2. Сколько комбинаций дублируют родителя.
3. Что уже живёт в портале: адреса и способ закрытия от индекса (`/find` и фильтры: `noindex, follow`, canonical без фильтров — подтвердить по коду).
4. Есть ли sitemap, сколько в нём URL, какие типы.
5. Какие локали реально переведены.
6. **Согласованность чисел:** число программ на странице страны или вуза и число в выдаче `/find` при тех же фильтрах считаются одним запросом или разными; есть ли расхождения (R-4.4.11 ТЗ).
7. Нагрузка: насколько выдача `/find` защищена от перебора (лимит запросов, проверка ботов), потому что страницы-маршруты ведут на неё.

## Формат результата

Файл `seo-volume-report.md`:

1. Шапка: дата, версия кода и базы, СУБД, способ счёта.
2. **Главная таблица:** строка на тип T01…T53, столбцы возможных, K1, K2, K3, K4, K5; базовый сценарий; ниже такие же для мягкого и жёсткого.
3. Таблица причин по K2: тип × причина × страниц × страниц «только с этой причиной».
4. Чувствительность (шаг 4).
5. Происхождение × назначение: таблица T30–T36 по уровням и число стран отправления с данными.
6. Слепые зоны (шаг 5).
7. Не найдено и допущения.
8. Запросы: каждый текстом, чтобы число воспроизводилось.

Числа без запроса не принимаются. Если счёт невозможен, писать «не посчитано: причина и что добавить в данные», не оценивать на глаз.

## Пример запроса (Postgres; имена условные)

```sql
-- T20 направление × страна
SELECT count(*) FROM (
  SELECT i.country_iso2, p.field_id
  FROM program p JOIN institution i ON i.id = p.inst_id
  GROUP BY 1, 2
  HAVING count(*) >= :p_prog AND count(DISTINCT p.inst_id) >= :p_inst) t;

-- T21 направление × город
SELECT count(*) FROM (
  SELECT i.city_id, p.field_id
  FROM program p JOIN institution i ON i.id = p.inst_id
  GROUP BY 1, 2 HAVING count(DISTINCT p.inst_id) >= :p_inst) t;

-- T30 пары «страна отправления → страна назначения» с собственными данными
-- (имена visa_rule и citizenship_price условные: найти реальные на шаге 0)
SELECT count(*) FROM (
  SELECT d.country_iso2 AS dest, o.iso2 AS origin,
         (v.id IS NOT NULL)::int + (c.id IS NOT NULL)::int AS blocks
  FROM (SELECT DISTINCT i.country_iso2 FROM institution i
        JOIN program p ON p.inst_id = i.id) d
  CROSS JOIN country o
  LEFT JOIN visa_rule v ON v.origin = o.iso2 AND v.dest = d.country_iso2
  LEFT JOIN citizenship_price c ON c.origin = o.iso2 AND c.dest = d.country_iso2
  WHERE o.iso2 <> d.country_iso2) t
WHERE blocks >= 2;
```

## Ограничения

- Только чтение. Персональных данных пользователей не выгружать: нужны агрегаты по справочникам.
- Не выдумывать числа и названия таблиц.
- Названия методик BFAS/Big Five и RIASEC в отчёте не использовать; параметр `riasec` называть «тип работы».
- Решения о том, что включать в индекс, не принимать: результат отдать владельцу проекта как есть.
