# 25. Матрица доступа: что она даёт для уникализации и объёма SEO-страниц

Актуально на 13.11.2026. Версия 1. Основание: решение владельца ВЛ-11 (`docs/22`) и матрица `vault/portal-filters/Матрица доступа.html` (черновик команды, статус «предложение»; данные на 13.11.2026, 03:39; поиск собран 12.11.2026, 23:39 UTC). Таблицы ниже разобраны программно из файла и пересчитаны; цифры матрицы — Ф, расчёты — В, предложения — П.

## 1. Что такое матрица

Для каждого типа страницы (страна, город, регион, направление, профессия, вуз, колледж, программа, подборка, статьи, языковые школы и курсы, эксперты, тесты, подбор, личный кабинет, служебное) в ней два слоя:

1. **Атрибуты и их заполняемость** в процентах по базе (это «вес» параметра: на какой доле сущностей параметр есть), с динамикой «было → стало» с 12.11.2026.
2. **Блоки на странице × пять аудиторий**: поисковый робот, гость, после входа, после оплаты, команда. Значки: ✓ виден, ◐ частично, ✕ не виден.

Базовые объёмы (Ф): 848 942 программы, 22 669 вузов, 23 054 колледжа, 81 страна, 10 699 городов с программами, 744 региона со справкой (из 1 076), 12 направлений, 480 профессий локально (на серверах 4 497), 1 587 языковых школ, 85 677 курсов, 145 организаций. Ещё 202 948 программ с ценой только для местных вне выборки (CN 76 033, RU 47 528, UA 28 191).

## 2. Как матрица меняет ТЗ

### 2.1 Граница данных по колонке «Поисковый робот»

Колонка робота становится верхней границей того, что страница режима контента может показывать (`docs/22`, R-4.4.1):

| Значок для робота | Смысл для ТЗ |
|---|---|
| ✓ | блок разрешён в HTML (если не нарушает ВЛ-10/ВЛ-11, см. 2.2) |
| ◐ | разрешён частично; в матрице «что именно» не заполнено, нужно решение (О-17) |
| ✕ | в HTML нет |

Сводка по колонке робота (блоки на странице):

| Тип | Блоков | ✓ | ◐ | ✕ | Страница для робота |
|---|---|---|---|---|---|
| Страна | 8 | 6 | 2 | 0 | ✓ |
| Город | 4 | 3 | 1 | 0 | ✓ |
| Регион | 1 | 1 | 0 | 0 | ✓ |
| Направление | 5 | 3 | 2 | 0 | ✓ |
| Профессия | 8 | 3 | 4 | 1 | ✓ |
| Вуз | 8 | 6 | 1 | 1 | ✓ |
| Колледж | 1 | 1 | 0 | 0 | ✓ |
| **Программа** | 9 | 0 | 4 | 5 | **✕** |
| Подборка, посадочные, поиск | 6 | 3 | 3 | 0 | ✓ |
| Эксперты и организации | 8 | 0 | 0 | 8 | ✕ |
| Тесты, подбор, личный кабинет, служебное | 22 | 0 | 0 | 22 | ✕ |

Главное: **страница программы сейчас закрыта от робота**; решение ВЛ-11 это меняет (программа становится страницей режима контента) — расхождение с матрицей, вносится в неё как изменение.

### 2.2 Расхождение матрицы с ВЛ-10 и ВЛ-11

ВЛ-10/ВЛ-11: на страницах режима контента нет значений из базы по вузам и программам. Матрица разрешает роботу агрегаты:

| Страница | Блок, ✓ для робота | Расхождение с ВЛ-11 |
|---|---|---|
| Страна | число вузов и программ; цены обучения; цены под своё гражданство и валюту; стоимость жизни; условия и шаги поступления | числа и цены уровня страны (агрегаты, не записи) |
| Город | число вузов и программ; популярные направления; цены обучения | то же, уровня города |
| Направление | число программ по странам; связанные профессии; экзамены | число программ по странам |
| Вуз | название, адрес, сайт, контакты; тип и аккредитация; **число программ по направлениям; цены обучения; ближайший срок подачи**; кампусы | числа и цены **уровня вуза** — прямое нарушение ВЛ-11 |
| Профессия | описание; прогноз спроса; профессии по сферам | расхождений нет |

**Предложение (О-17).** Правило ВЛ-11 применять на уровне записей: не показывать списки программ и вузов и числа, цены, сроки на уровне **одного вуза и одной программы**. Агрегаты уровня страны, города, региона, направления (число программ, средняя цена, стоимость жизни, виза) считать разрешёнными: они не позволяют выгрузить базу и они же дают главный материал для уникализации (раздел 3). Если ВЛ-11 толковать строже матрицы, объём уникализации падает на порядок.

### 2.3 Вес параметра как порог создания блока

Заполняемость задаёт, на каких страницах параметр можно ставить в обязательный блок. Предложение (П): параметр входит в обязательные блоки типа, если заполнен ≥ 50 % сущностей; от 20 до 49 % — необязательный блок (страница без него остаётся K1, но с пометкой неполноты); < 20 % — не используется для уникализации, пока не поднята заполняемость.

Вывод (В): **объём страниц растёт от сильных типов к слабым, а данных для уникализации — наоборот.**

- **Сильные типы** (страна, направление, профессия, город, регион): мало страниц, почти все параметры заполнены. Здесь можно строить богатые блоки.
- **Слабые типы** (вуз, колледж, программа): много страниц, заполнена в основном «идентичность». У программы описание заполнено у 8 % (≈ 67 915 из 848 942), «чему научится выпускник» у 3 % (≈ 25 468), «как учат и как оценивают» у 2 %, модули и учебный план у 5 %. Остальные 90 %+ страниц программ в режиме контента будут тонкими.

Параметры страны и города, пригодные как уникальные блоки в режиме контента (≥ 50 %, не записи вузов; Ф):

| Блок | Параметр (заполняемость) |
|---|---|
| Виза и въезд | нужна ли виза и какая (74 %), визовый сбор (67 %), работа во время учёбы (63 %), работа после выпуска (54 %) |
| Деньги | цены под своё гражданство и валюту (100 %), средняя цена и диапазон (84 %), аренда жилья по городам (58 %), стоимость жизни в месяц (48 %, чуть ниже порога) |
| Поступление | сроки подачи (62 %), учебный календарь (48 %), стипендии для иностранцев (85 %), условия: язык, деньги, аттестат (44 %) |
| Экономика | зарплаты (94 %), безработица, инфляция, налоги (95 %), иностранные студенты: число и доля (86 %), охват высшим образованием (91 %) |

Эти параметры делают для пары «из X в Y» реально разные страницы: виза, цены под гражданство и валюту, признание условий зависят от страны отправления. Это закрывает проблему, найденную в образцах (`docs/22`, R-4.4.5: 58–67 % одинаковых предложений): блоки строятся из данных, а не из шаблонного текста.

Слабые места, которые матрица называет сама (Ф): сколько денег показать для визы 23 %, страховка 42 %, шаги поступления и сбор 38 %, общежитие: цена 43 %, стоимость жизни по Numbeo в городах < 1 %, сроки подачи в вузах города 15 %. Пары, где этих данных нет, остаются K2 до заполнения.

## 5. Что матрица меняет в классах K1–K5

- **K1 (в индекс)** для типов режима контента: страница проходит R-4.4.4 (≥ 6 блоков) **из блоков с робот-значком ✓ и заполняемостью ≥ 50 %**, и R-4.4.5 (доля общих предложений с соседями ≤ 40 %).
- **K2 (после уникализации)**: причина — блок не набирает 50 % по сущности (например, «шаги поступления» 38 %, «деньги для визы» 23 %) либо нет редакционного текста.
- **Программы**: до подъёма заполняемости описания (8 %) индексируемыми остаются ≈ 68 тыс. программ с описанием; остальные получают canonical на страницу вуза (K3) или `noindex` (K4); это сокращает потолок T06 с 848 942 до порядка 10⁴–10⁵ (В).
- **Вуз и колледж**: при средней заполняемости 41 % часть страниц будет K2; основная опора уникальности — контекст города и страны (раздел 3).

## 8. Проверка по правилам проекта

- Цифры матрицы даны как есть, с датой (13.11.2026); расчёты помечены В; потолки не подаются как факт индекса.
- Матрица названа черновиком: решения на ней строятся только после О-22.
- Названия методик не используются; параметр «тип личности» в публичные блоки не выносится.
- Данные несовершеннолетних: колонки «после входа» и «после оплаты» (кабинет, подбор для ребёнка, отчёты) в публичные страницы не попадают; робот видит ✕.
