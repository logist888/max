# 15. Партнёрская сеть: техническое задание на первый запуск

Назначение: рабочий документ для двух аудиторий — разработки (что построить и как проверить) и партнёрской сети (по каким правилам подключать партнёров и что им давать). Актуально на 09.09.2026. Основан на каноне `docs/14-partner-network.md`, транскрипте созвона 09.09 (`raw/2026-09-09-partnerka/`), внешнем отчёте «Стратегия партнёрской сети» (ChatGPT, 20 стр., тот же каталог), разборе четырёх независимых агентов (продукт и методология; маркетинг и путь партнёра; интерфейс и путь семьи; финансы, право и данные) и критике красной команды (раздел 13).

Как читать. Разработка: разделы 3–8 и 10. Координатор партнёрской сети: разделы 2, 9, 11. Основатель: разделы 1, 7.3, 11, 13. Каждое требование имеет идентификатор (ПРОД, МАРК, ИНТ, ФИН, ДАН, ПРАВ) и источник: Т — транскрипт 09.09, К — канон, В — внешний отчёт, А — вывод агента, П — предложение этого документа. Статусы: **принято**, **на пилот** (рабочее значение, пересматривается), **отложено**, **к проверке**.

Все цены — рабочие значения пилота для России, названы 09.09 «по ощущению продукта», не измерены: сумма платформы z = 15 000 ₽, МРЦ y = 20 000 ₽, РРЦ x = 35 000 ₽, публичная цена сайта p = 50 000 ₽. В интерфейсе и материалах рядом с буквой всегда слово и сумма; в интерфейсе партнёра букв нет вовсе (ИНТ-02).

## 4. Правила и проверки на сервере

| Правило | Формулировка | Источник |
|---|---|---|
| Цена | k ≥ y варианта; k ≤ k_max политики, если задан (умолчание пилота 50 000); проверка по итоговой цене после всех кодов | Т, К, П |
| Один продукт | На пилоте выбираем только SKU «Россия, рубли»; иные страны и продукты недоступны | Т |
| Страна | Страна предложения — по SKU; страна покупателя проверяется при заказе (критерий — решение разработки и юриста); несовпадение блокирует заказ с объяснением | К |
| Неизменяемость | k, sku_id, terms_id предложения не редактируются; допустимы только stop и продление valid_to; изменение цены — новое предложение | Т, А |
| Заказ до платежа | Заказ со снимком создаётся на сервере до создания платежа; сумма платежа равна k заказа; e-mail подтверждён до платежа | А, `docs/02` |
| Переход не продажа | Открытие страницы фиксируется как переход; начисление только по PaymentConfirmed от шлюза; страница успеха в браузере — не подтверждение | В |
| Доступ после оплаты | Доступ семье выдаётся только после PaymentConfirmed; аккаунт семьи создаёт семья, не партнёр, в обоих маршрутах | В, А |
| Одна оплата — одно начисление | Атрибуция по offer_id заказа; несколько источников одной семьи — фиксируется при создании заказа; ручная смена только с причиной и журналом | В |
| Зачёркнутая цена | Показывать p зачёркнутой, только если direct_sale_active истинен и k < p; иначе только k. Пока флаг ложен, p партнёрам не называется: условия и материалы существуют в двух редакциях — «с ценой сайта» и «без сравнения» (К03, К04, К06, К07) | Т, В, ПРАВ-05, А |
| Удержание | accrual.available наступает при min(max(PaymentConfirmed + H, report_delivered + H₂), PaymentConfirmed + H_max) и отсутствии открытого спора по заказу. Открытый спор — обращение о возврате в состоянии opened или in_review, либо PaymentChargebacked без закрытия. Спор блокирует только спорный заказ. Первые N выплат партнёра (параметр, умолчание 3) и любые начисления по заказам с k > x подтверждаются владельцем платежей вручную | А (ст. 32), красная команда |
| Возврат | Рассмотрение возврата семье и корректировка партнёру — раздельные записи, связанные order_id; полный возврат обнуляет начисление; частичный — по параметру распределения; **умолчание — каскад: возвращаемая сумма сначала уменьшает начисление партнёра до нуля, затем сумму платформы** (пропорция как умолчание отклонена: она позволяет партнёру и семье сговором получить продукт дешевле z) | В, А, красная команда |
| Возврат после выплаты | Создаёт partner_debt; зачёт против будущих начислений; после N дней — списание в расход платформы с отдельным статусом; возврат семье не ждёт денег от партнёра | В, А |
| Самореферал | Заказ с признаками ДАН-10 помечается; начисление остаётся в held до решения владельца обращений; покупка партнёром из своего аккаунта по своему коду начисления не создаёт. Покупка через родственника признаками не ловится — команда либо принимает это как допустимую скидку «своим», либо задаёт дополнительные признаки (11.15) | В, А |
| Запреты показа | Партнёру: данные ребёнка, содержание отчёта, чужие сделки, w; семье: Δ и z | К, правила проекта |
| Индексация | Страницы предложений — noindex; приватные данные — только за авторизацией | В |

## 5. Состояния и переходы

| Объект | Состояния | Переходы и условия |
|---|---|---|
| Партнёр (жизненный цикл) | потенциальный → подключённый → активированный → продающий; признак «повторно активный» независим | подключённый: оферта принята; активированный: первое «обращение» (событие определяется, 11.9); продающий: первая PaymentConfirmed; повторно активный: оплата или обращение второй семьи |
| Партнёр (выплаты) | статус не указан → указан (физлицо, НПД, ИП) → подтверждён | выплата возможна только из «подтверждён»; кабинет работает в любом |
| Предложение | active → stopped; active → expired | stop — действие партнёра или координатора; expired — по valid_to; обратно в active нельзя |
| Заказ | created → awaiting_payment → paid → access_granted → in_progress → delivered; из любого: cancelled; из paid и далее: refund_requested → refunded (полный или частичный); chargebacked | paid только по PaymentConfirmed; delivered по report_delivered_at. Маршрут 2: created → sponsored (по SponsorPaymentConfirmed) → access_granted, без paid и без начисления |
| Платёж | pending → confirmed; pending → failed → retry (тот же заказ); confirmed → refunded_partially, refunded, chargebacked | повтор уведомления не меняет состояние второй раз; PaymentChargebacked создаёт adjustment типа chargeback и, если выплата прошла, partner_debt |
| Начисление | held → available → paying → paid; held или available → reversed (полный возврат или опротестование). Частичная корректировка состояние не меняет: AccrualAdjusted уменьшает current_amount | available по правилу удержания; paying при формировании реестра; paid по подтверждению банка; PayoutFailed возвращает в available с причиной |
| Выплата | draft → sent → confirmed; sent → failed | failed сохраняет обязательство; повтор после исправления реквизитов |
| Долг партнёра | open → offset (частично или полностью) → closed; open → written_off | зачёт только против available |
| Обращение о возврате | opened → in_review → approved (сумма) или declined → closed | approved создаёт refund и adjustment |

## 7. Расчёты

### 7.1 Партнёр

Начислено по заказу (gross): по accrual_formula политики предложения; в пилоте Δ = k − z. Корректировки меняют текущую сумму начисления: current = gross + Σ adjustments (adjustments ≤ 0). Период: начислено A = Σ gross; корректировки C = Σ adjustments; доступно D = Σ current по начислениям в состоянии available − открытые долги партнёра; к переводу N = D − удержания по статусу (7.4). Выплаченное не вычитается из D: выплаченные начисления находятся в состоянии paid и в сумму available не входят. Партнёру показываются A, C, D, N раздельно; «прибыль» не показывается — только «до ваших налогов и расходов».

### 7.2 Платформа по заказу

Результат = k − fee(k) − tax(k или z по режиму) − Δ − w. Константа «15 000» не используется (ФИН-01). Для продуктов экспертов (отложено) слои: k = v + a + m + f; при процентном сборе f = r·k цена k = v/(1 − r); проценты от разных баз не складываются (взято из внешнего отчёта).

### 7.3 Налоговый слой: что зависит от k

Тезис «платформа всегда получает 15 000» неверен для маршрута 1: платформа получает всю k, и её оборотные расходы растут с k. Ставки ниже — параметры, не факты; режим ИП в источниках не назван.

|---|---|---|---|---|---|---|---|---|---|
| 20 000 | 20 000 | 500 | 5 000 | 1 200 | 13 300 | 2 175 | 12 325 | 1 500 | 11 800 |
| 35 000 | 35 000 | 875 | 20 000 | 2 100 | 12 025 | 2 119 | 12 006 | 6 000 | 6 025 |
| 70 000 | 70 000 | 1 750 | 55 000 | 4 200 | 9 050 | 1 988 | 11 262 | 16 500 | −7 450 |
| 1 000 000 | 1 000 000 | 25 000 | 985 000 | 60 000 | −70 000 | 10 000 | −20 000 | 295 500 | −365 500 |

Точка нуля при УСН «доходы» и партнёре со своим налоговым статусом: k = z/(t + a) ≈ 176 000 ₽. Если партнёр — физлицо без статуса и платформа платит взносы 30 % на Δ (7.4), точка нуля k = (z + 0,3·z)/(t + a + 0,3) ≈ 50 600 ₽: при умолчании k_max = 50 000 результат платформы до себестоимости около 250 ₽. Взносы уменьшают налог УСН до половины — учтено в пользу платформы не полностью; порядок величин это не меняет. Зарубежная карта (комиссия 10 % по `docs/06`): при k = 35 000 эквайринг 3 500 — четверть z. Команда сама назвала эффект на созвоне («с миллиона мы заплатим 60 000 налогов» — это 6 %, косвенно указывает на УСН «доходы»), но не перенесла его в формулу.

Конструкции, при которых результат платформы не зависит от k (решение основателя с бухгалтером и юристом, 11.2):

| Конструкция | Результат платформы | Плюсы | Минусы | Цена ошибки |
|---|---|---|---|---|
| А. z сверх оборотных расходов: платформа удерживает z + t·k + a·k; партнёру Δ = (1 − t − a)·k − z | z − w при любой k | Честно, одна формула, без юриста | Ломает лозунг «вся наценка партнёру»; ставка t раскрывается партнёру | Низкая |
| Б. Маршрут 2: доход платформы только z | ≈ z − (t + a)·z | Простая база | Продавец семье — партнёр (ПРАВ-07) | Высокая до заключения |
| В. Расщеплённый платёж: k = z (услуга платформы) + (k − z) (услуга партнёра семье, платформа — агент партнёра) | ≈ z − t·z − a·k | Налог только с z | Партнёру нужен статус; чек агента; семья покупает «две услуги»; эквайринг от k | Высокая: риск переквалификации |

Умолчание пилота при отсутствии решения: конструкция Г с k_max = p = 50 000 на маршруте 1 и запрет маршрута 2. Результат платформы до себестоимости при k = 50 000 и УСН «доходы»: 10 750 ₽, если партнёр самозанятый или ИП; около 250 ₽, если партнёр физлицо без статуса. Это предохранитель, не позиция: если основатель хочет, чтобы физлица продавали по 50 000, нужна конструкция А, либо k_max для физлиц на уровне 35 000 (результат 6 025). Формула начисления — параметр политики (accrual_formula), чтобы решение не переписывало сущности и экраны.

### 7.4 Выплаты и статус партнёра

Допущение «мы не налоговый агент, партнёр платит НДФЛ сам по оферте» для физлица без статуса не работает: обязанности налогового агента (ст. 226 НК) и страховые взносы по гражданско-правовым договорам (ст. 420, 425 НК) установлены законом, договором не снимаются — к юристу (ПРАВ-01). Три ветки выплаты по tax_status: физлицо-резидент — удержание НДФЛ (ставка — параметр, прогрессия) и взносы сверх Δ за счёт платформы; самозанятый — проверка статуса и чек «Мой налог» в день выплаты, предмет договора не агентский (ПРАВ-02), годовой лимит режима 2,4 млн ₽ — параметр контроля; ИП — счёт и акт. Нерезиденты (в том числе преподаватели в Грузии из плана канона) и юрлица в пилоте не выплачиваются: ставка НДФЛ нерезидента, валютный контроль и требования 115-ФЗ — отдельное заключение (ПРАВ-11). При k = 35 000 и партнёре-физлице: обещано 20 000, к выплате 17 400, платформа несёт ещё 6 000 взносов — это должно быть видно в интерфейсе до подключения, а не при выплате.

### 7.5 Возвраты

Полный возврат до выплаты: refund на k, accrual → reversed, комиссия шлюза при возврате — расход платформы (fee_lost, уточнить у платежей). Частичный возврат u: распределение по параметру; умолчание — каскад: сначала уменьшается начисление партнёра (до нуля), затем сумма платформы. Пропорциональное распределение отклонено как умолчание: при k = 35 000 и возврате 20 000 партнёру оставалось бы 8 571, платформе 6 429 за полностью оказанную услугу, а семья фактически заплатила бы 15 000 — сговор партнёра и семьи выгоден обоим. Возврат после выплаты: refund семье немедленно; partner_debt на долю партнёра; зачёт против будущих начислений; списание после N дней.

Опротестование платежа (chargeback). Держатель карты может оспорить платёж через банк в срок, многократно превышающий H (порядок — месяцы). Сценарий вывода денег: партнёр создаёт предложение на максимальную цену, «семья» платит подконтрольной картой, партнёр получает Δ через 14 дней, платёж оспаривается — платформа возвращает k, долг с физлица не взыскать. Предохранители: k_max (умолчание 50 000); первые N выплат партнёра и все заказы с k > x — ручное подтверждение платежей; выплата не раньше выдачи отчёта (H₂) или H_max; пометка самореферала (ДАН-10). Полностью риск снимает только удержание на срок оспаривания, что для партнёра неприемлемо; остаток риска — осознанный. Момент «услуга оказана» (выдача отчёта) и фактические расходы исполнителя при отказе — к юристу (ПРАВ-06); правило возврата в трёх состояниях (до начала теста, после начала, после выдачи отчёта) — параметры системы (ПРОД-13).

### 7.6 Панель пилота

Счётчики, без процентов при n < 10: содержательные контакты; подключения; предложения; переходы; обращения (по определению 11.9); оплаты; доставленные отчёты; сбои доступа; возвраты (число и сумма); начислено, удержано, доступно, выплачено; долги; повторные продажи; время команды; бесплатные прохождения блогеров (число × w). Разрезы: когорта, партнёр, предложение, цена, неделя. Отдельно от метрик потока 1 и вебинарной воронки.

## 10. Критерии приёмки

Принимают вместе маркетинг, продукт, разработка и платежи; результат — записи тестовых заказов и найденных ошибок; после исправлений один реальный полный цикл. Скриншотов кабинета недостаточно.

| № | Проверка | Ожидаемый результат |
|---|---|---|
| 1 | Предложения по минимальной, рекомендованной и максимальной цене (20 000, 35 000, 50 000) | Заказ проходит; сумма платежа и начисление совпадают с предложением |
| 2 | Цена ниже 20 000; выше k_max (при умолчании 50 001); подменённая в запросе | Сервер отклоняет; платёж не создаётся |
| 3 | Два предложения одного партнёра с разными ценами; третье остановлено | Каждая ссылка ведёт на свою цену; создание нового не меняет оплаченные заказы; остановленная показывает «завершено» |
| 4 | Истёкшее предложение и неоплаченный заказ | Показан статус; новая цена только после явного подтверждения |
| 5 | Семья пришла по двум ссылкам | Одна оплата — одно начисление по правилу атрибуции; журнал источника |
| 6 | Успех, ошибка и повтор платежа; двойное уведомление шлюза | Доступ только после подтверждения; повтор не дублирует доступ и начисление |
| 7 | Оплата без доступа или без отчёта | Сигнал владельцу обращений; восстановление по номеру заказа; статус «готово» не выставляется |
| 8 | Полный и частичный возврат до выплаты | Обращение, деньги семье и корректировка партнёру связаны одним заказом; частичный возврат уменьшает сначала начисление партнёра (каскад) |
| 9 | Возврат после выплаты | Семье возвращено; долг партнёра создан и виден; зачёт против следующего начисления |
| 10 | Удержание, допуск, выплата, отказ банка | Начисление проходит состояния; неуспешный перевод не списывает обязательство |
| 11 | Подмена чужого partner_id; покупка по своему коду | Чужие данные недоступны; самореферал без начисления и с пометкой |
| 12 | Материалы и обещания | Цена, состав, срок, продавец и выплаты согласованы между К01–К12, страницей семьи и оферой |
| 13 | Выплата партнёру-физлицу без статуса | Блокирована до ввода статуса; при статусе «физлицо» показаны удержания |
| 14 | Заказ без выданного отчёта на 15-й день; тот же заказ на 61-й день без спора | На 15-й день начисление не доступно; на 61-й — доступно (H_max) |
| 15 | Зачёркнутая цена при выключенном флаге прямой продажи | На странице семьи только k; в условиях партнёра цена сайта не упоминается |
| 16 | Предложение k = 200 000 | При умолчании k_max = 50 000 отклоняется сервером; при k_max = «нет» создаётся с внутренним сигналом (ФИН-12), партнёр видит только «дороже рекомендованной» |
| 20 | Смена ценовой политики (z 15 000 → 18 000) при активных предложениях | Активные предложения истекают с уведомлением; начисления по оплаченным заказам не меняются |
| 21 | Опротестование платежа после выплаты партнёру | Платёж → chargebacked; adjustment типа chargeback; долг партнёра создан; семья и заказ связаны |
| 22 | Первая выплата нового партнёра; выплата по заказу с k = 45 000 | Обе требуют ручного подтверждения владельца платежей (ФИН-13) |
| 23 | Партнёр с tax_status «нерезидент» или «юрлицо» | Выплата блокирована с объяснением; кабинет работает |
| 17 | Маршрут 2 (если включён): доступ семье без оплаты z | Невозможен; лимит доступов срабатывает |
| 18 | Партнёр открывает результаты | Нет имён, возраста, содержания отчёта; только статусы и суммы |
| 19 | Тексты интерфейса и материалов | Нет букв x, y, z, k в кабинете партнёра; нет названий методик под лицензией |

## 13. Разбор красной команды

Черновик ТЗ отдан независимому субагенту без указания авторства; получено 22 претензии, арифметика раздела 7 и ссылки на нормы пересчитаны им отдельно (все расчёты таблицы 7.3 подтверждены). Разбор:

**Подтверждено и внесено.**
1. Два несовместимых умолчания по верхней границе (1.2 «нет» против 7.3 «50 000») — оставлено одно: k_max = 50 000; ИНТ-04, МАРК-02, приёмка 1, 2, 16 переписаны под него.
2. Безлимитная цена плюс выплата через 14 дней — канал вывода денег через опротестование платежа; добавлены 7.5 (сценарий и предохранители), ФИН-13 (ручное подтверждение первых выплат и заказов дороже РРЦ), приёмка 21, 22.

**Спорно, оставлено с оговоркой.**
- Объём MVP (претензия 7): полное ТЗ сохранено, потому что решения основателя (11.2, 11.3) могут потребовать конструкцию А уже в пилоте; разметка объёма показывает, что строить сначала.

## 14. Проверка по правилам проекта

Поток: 2, канал отдельный; продажи консультаций 250 000–500 000 из транскрипта — поток 1, в экономику канала не входят; панель не смешивается с потоком 1 и вебинаром (МАРК-12). Цели привлечения экспертов: канал — дистрибуция, не валидация продукта; при этом партнёрские семьи проверяют центральную гипотезу конверсии без предупреждения об этом — риск назван (11.12, персонажи семей). Названия методик: не использованы; проверка образца и текста отчёта — ПРОД-06, приёмка 19. Данные несовершеннолетних: партнёру виден только статус (ИНТ-17, ПРОД-09, ПРАВ-10). Цифры: значения России — рабочие значения пилота; ставки налогов и эквайринга — параметры с явными допущениями; медиана рынка и число продаж на партнёра — память участников, источников нет. Правовые пункты — вопросы к юристу с нормой, не заключения. Имена: только те, что есть в каноне; ответственные — по направлениям.
