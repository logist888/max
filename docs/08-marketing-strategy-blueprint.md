# 08. Эталон отчёта по маркетинговой стратегии — структура и содержание

Снимок 24.06.2026. Документ синтезирован из мирового канона (Kotler/Keller, Kotler/Armstrong, McKinsey/Minto, HubSpot, академические гайды) через состязательно проверенное исследование (22 подтверждённых факта из 25, 21 источник). Это **бланк-методология**: какой должна быть структура и наполнение отчёта по маркетинговой стратегии для MainExperts, а не сам отчёт. Сам отчёт собирается по этому каркасу из `docs/01–07`.

> Критическая рамка. Канон ниже — это **сходящийся консенсус источников, а не обязательная последовательность**. Исследование отдельно отвергло (0 из 3 голосов) утверждения о «единственно правильном жёстком порядке разделов»: его нет. Порядок подчиняется логике доказательства, а не ритуалу. Берём логику, не нумерацию.

## Часть A. Что показал мировой канон

### A1. Две школы дают один скелет

Классики маркетинга сходятся на 5–8 блоках, различаясь дроблением, не сутью.

- **Kotler & Keller** (Marketing Management, гл. 2) — 5 разделов: (1) резюме и оглавление, (2) ситуационный анализ, (3) маркетинговая стратегия, (4) финансовые проекции, (5) контроль реализации. *[подтверждено 3-0]*
- **Kotler & Armstrong** (Principles of Marketing, Прил. 1) — 8 разделов: резюме → текущая ситуация → угрозы и возможности (SWOT) → цели и проблемы → маркетинговая стратегия → программы действий → бюджеты → контроль. *[подтверждено 3-0]*
- **Гайд UMGC** — 6 разделов: резюме, ситуационный анализ, анализ рынка, рыночная стратегия, финансовый анализ, реализация и контроль. *[подтверждено 3-0]*
- **HubSpot** (практик-шаблон) — 7 компонентов: резюме, анализ целевого рынка, конкурентный анализ, стратегии, тактики, бюджет и календарь, метрики. *[подтверждено 2-1]*

**Инвариант (то, что есть у всех):** резюме → ситуационный анализ → стратегия (цели + STP) → тактика/программы → финансы/бюджет → реализация и контроль.

### A2. Два уровня внутри документа

Маркетинговый план работает на **двух уровнях — стратегическом и тактическом** *[подтверждено 3-0]*. Стратегический отвечает «куда и почему» (рынок, сегменты, позиционирование, ценность). Тактический — «чем и когда» (каналы, кампании, календарь, бюджет по статьям). Их нельзя смешивать в одном разделе: стратегия без тактики не исполнима, тактика без стратегии не объяснима.

### A3. Обязательные содержательные стандарты

- **Цели — по SMART:** конкретные, измеримые, с горизонтом. Декларация «вырасти» целью не является. *[подтверждено 3-0]*
- **Ядро стратегии — STP:** сегментация → таргетинг → позиционирование, плюс маркетинговые цели. *[подтверждено 2-1]*
- **Ситуационный анализ — с макросредой (PESTEL):** не только конкуренты и продукт, но политико-правовой, экономический, социокультурный, технологический контекст. Для MainExperts это критично: данные несовершеннолетних, регуляторика СНГ/MENA. *[подтверждено 3-0]*
- **Контур измерения обязателен:** план должен задавать, **как меряется прогресс к целям**. *[подтверждено 3-0]* (Конкретный список KPI единого канона не имеет — исследование отвергло жёсткий перечень HubSpot 1-2; набор метрик выбирается под модель.)

### A4. Консалтинговая форма подачи (McKinsey / Minto)

Содержание — половина дела; вторая половина — **порядок изложения, дающий доказательность**.

- **Принцип пирамиды** (Барбара Минто, McKinsey): сверху вниз — одна управляющая мысль (главная рекомендация) → 3–5 поддерживающих аргументов → данные/доказательства под каждым. Вывод первым, обоснование следом. *[подтверждено 3-0]*
- **Зачин SCQA / SCR:** Ситуация → Осложнение → Вопрос → Ответ (Situation–Complication–Resolution). Документ открывается не данными, а напряжением, которое он снимает. *[подтверждено 3-0]*
- **MECE:** разделы взаимоисключающи и совместно исчерпывающи — без дыр и пересечений.

Для MainExperts это означает: отчёт открывается не «рынок EdTech растёт», а конфликтом — «реальная выручка идёт из потока 1 по рекомендациям, но цель $1 млн зашита в недоказанную воронку потока 2; чем закрываем разрыв».

### A5. Отраслевой слой EdTech

- **Полноворончатая модель из 5 стадий:** Awareness → Evaluation → Conversion → Adoption → Retention/Expansion. Retention названа самым недооценённым источником выручки. *[из поиска, отраслевой консенсус]*
- **Разрыв «покупатель ≠ пользователь»** — родовая черта EdTech: платит родитель, пользуется подросток. Сообщения и воронка должны адресовать обоих, на стыке — точка падения конверсии. *[из поиска]*
- **Триггеры free→paid в EdTech** (не контент сам по себе): подотчётность/структура, ценность сертификата/диплома, разблокировка функции, к которой пользователь привык. *[подтверждено]*
- **Распределение бюджета по воронке** как ориентир: ~60% awareness / 25% consideration / 15% conversion. *[supporting, один источник — брать как гипотезу, не норму]*

## Часть B. Эталонная структура отчёта для MainExperts

Каркас ниже адаптирует инвариант A1 под две жёсткие особенности проекта: **два несмешиваемых потока выручки** и **недоказанную центральную гипотезу**. Каждый раздел — что обязан содержать, чтобы отчёт был информационно достаточным.

### 0. Резюме для руководителя (Executive Summary) — 1–2 стр.

По пирамиде Минто: сначала ответ. Главная рекомендация, 3–5 опор, ключевые цифры (цель, сроки, бюджет, ожидаемая экономика по каждому потоку отдельно). Зачин по SCQA. Пишется последним, читается первым. **Разнести поток 1 и поток 2 уже здесь** — единой цифрой $1 млн открываться нельзя (см. `01-strategy.md`, противоречие №2).

### 1. Ситуационный анализ

- **1.1. Макросреда (PESTEL) по двум регионам** — СНГ и MENA раздельно. Обязательно: регуляторика данных несовершеннолетних, статус психодиагностики, лицензионный риск (см. `05-risk-compliance.md`). По MENA источники фрагментированы и за пейволом — помечать пробелы, не выдумывать.
- **1.2. Рынок и спрос** — объём, динамика, готовность платить. РФ-рынок труда через api.hh.ru; профессии — O*NET/ESCO. MENA — с оговоркой о качестве данных.
- **1.3. Конкуренция** — профориентация, EdTech-диагностика, премиальный консалтинг (для потока 1 — другое конкурентное поле, чем для потока 2).
- **1.4. Продукт и его состояние** — тест (рабочее название вместо BFAS/RIASEC — лицензии нет, см. правило 2) + AI-отчёт ~40 стр.; техсостояние и блокеры из `02-product.md`.
- **1.5. SWOT** — с честными слабостями: узкое место ручной экспертной проверки, недоказанная гипотеза, отсутствие лицензии на методики.

### 2. Цели и проблемы

- **2.1. Маркетинговые цели по SMART**, расщеплённые по потокам с разной экономикой. Не «$1 млн», а сколько и через какой поток, по каким срокам, с какой конверсией.
- **2.2. Зашитые противоречия** — вынести явно (масштабируемость узкого места, неразделённость потоков, статус гипотезы). Это требование критической рамки проекта, не опция.
- **2.3. Центральная гипотеза как ставка.** «Скрининг оцифровывает страхи родителя → родитель покупает диагностику» — пометить НЕ валидированной везде, где на ней стоит план. Указать, чем и когда проверяется (событие на развилке скрининга, первый вебинар).

### 3. Маркетинговая стратегия (STP) — раздельно по двум потокам

> Жёсткое правило проекта: метрики и каналы потоков не объединять. Поэтому раздел 3 ведётся в двух колонках, не в одной.

- **3.1. Сегментация и персонажи.** Четыре персонажа из `03-audience-custdev.md`. Явно держать разрыв «покупатель (родитель) ≠ пользователь (подросток)».
- **3.2. Таргетинг.**
  - *Поток 1 (HNW/UHNW, high-touch):* нетворкинг Дубая, private banking, рекомендации. Канал — не вебинар. Детали — в `private/stream-1-hnw.md`, в общий отчёт идёт обзорно.
  - *Поток 2 (freemium-воронка):* самообслуживание, вебинар как точка входа.
- **3.3. Позиционирование и ценность.** Мастер-миссия и сегментные ценности (родитель/подросток/взрослый) из `01-strategy.md`. Рабочие названия методик.

### 4. Тактика и программы действий

- **4.1. Воронка потока 2 по 5 стадиям EdTech** (Awareness→…→Retention). Карта: бесплатный скрининг → Профиль 10 (freemium) → Профиль 360 (апсейл) → подписки Free/Pro/Ultima. Триггеры free→paid обозначить явно (подотчётность, ценность отчёта+эксперта, разблокировка).
- **4.2. Каналы и слои трафика** — из `06-data-tools-payments.md`.
- **4.3. План первого вебинара** (предв. 4 июля 2026) — как тест гипотезы, с заранее заданным критерием успеха/провала.
- **4.4. Поток 1** — обзорно: цикл рекомендательных продаж, лесенка пакетов (детали конфиденциально).
- **4.5. Календарь** на горизонт 6 месяцев.

### 5. Бюджет и финансовая модель

- Раздельная экономика двух потоков (CAC/LTV считаются по-разному: high-touch vs self-serve).
- Декомпозиция цели $1 млн по потокам с проверкой на узкое место (≈1700 оплат пакета 50К ≈ 9–10/день ручной проверки — см. `01-strategy.md`).
- Ориентир распределения по воронке (60/25/15) — как гипотеза к проверке, не норма.

### 6. Измерение, реализация и контроль

- **6.1. KPI под модель** (не чужой шаблон): по потоку 2 — конверсии по стадиям воронки, free→paid, CAC/LTV, удержание; по потоку 1 — цикл сделки, конверсия рекомендаций. Метрики потоков не складывать.
- **6.2. Контур обратной связи** — как результат вебинара меняет гипотезу и план.
- **6.3. Ответственные** — обезличенно по направлениям (правило 7), кроме конфиденциального потока 1.

### Приложения

Реестр источников с датами и ссылками (правило данных 5); рабочие названия методик ↔ оригиналы (внутренне); глоссарий; детальные таблицы custdev.

## Часть C. Чек-лист информационной достаточности

Отчёт достаточен, если в нём есть:

- [ ] Резюме по принципу пирамиды — ответ первым, потоки разнесены.
- [ ] PESTEL по СНГ и MENA раздельно, с регуляторикой данных несовершеннолетних.
- [ ] SWOT с честными слабостями (узкое место, гипотеза, лицензии).
- [ ] Цели по SMART, расщеплённые по двум потокам.
- [ ] Центральная гипотеза помечена как ставка везде, где на ней стоит решение.
- [ ] STP в двух колонках (поток 1 / поток 2), без смешения метрик.
- [ ] Разрыв «покупатель ≠ пользователь» адресован в сообщениях и воронке.
- [ ] Воронка по 5 стадиям EdTech с явными триггерами free→paid.
- [ ] Бюджет с раздельной экономикой и проверкой цели на узкое место.
- [ ] Контур измерения: как меряется прогресс и как вебинар правит план.
- [ ] Каждый факт-премиум — с источником, датой, ссылкой.
- [ ] Рабочие названия методик вместо BFAS/Big Five/RIASEC.
