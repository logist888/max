# 07. Дерево наследования и дерево зависимостей

> Раздел 11 модуля DMS. Снимок 12.07.2026. Авторская разработка (Claude Code). Деревья
> показывают, как документы порождают друг друга (наследование) и что от чего зависит
> (зависимости). Опора: BABOK (requirements traceability), TOGAF (architecture continuum).
> Утверждает основатель.

Два дерева отвечают на два разных вопроса. **Наследование** — «откуда документ берёт полномочие
и смысл» (сверху вниз, от миссии к чек-листу). **Зависимости** — «без чего документ не может
существовать/исполняться» (может идти и горизонтально, между Divisions).

## 11.1. Дерево наследования (Inheritance Tree)

Канонический контур наследования (эталон из запроса), наполненный документами MainExperts.
Каждый уровень **выводит полномочие** из уровня выше: SOP не может противоречить Процедуре,
Процедура — Стандарту, Стандарт — Политике, Политика — Стратегии, Стратегия — Миссии.

```
Миссия / Ценности                     D7-POL-01
  └─ Стратегия                        D7-RMP-01 (Дорожная карта компании)  ·  ../11-gtm-strategy.md
      └─ Цели (Objectives)            в составе D7-RGS-01
          └─ OKR                      D7-RGS-01 (Реестр OKR)
              └─ Дорожные карты        D4-RMP-01 (продукт) · D2-RMP-01 (маркетинг) · D4-RMP-02 (тех)
                  └─ Проекты/Планы     D1-PLN-01, планы запуска (класс PLN)
                      └─ Процессы       P01–P12 (карта `02-process-map.md`)
                          ├─ Политики   D1-POL-*, D3-POL-*, D5-POL-* (рамка процесса)
                          ├─ Стандарты  D2-STD-*, D4-STD-*, D5-STD-* (норма результата)
                          ├─ Регламенты D2-RGM-02, D3-RGM-01, D6-RGM-01 (межфункц. порядок)
                          │   └─ Процедуры   D1-PRC-*, D4-PRC-01, D5-PRC-* (порядок функции)
                          │       └─ SOP     D2-SOP-02, D4-SOP-01, D5-SOP-01 (операция роли)
                          │           └─ Инструкции  WIN (шаг в инструменте)
                          ├─ Шаблоны    D2-TPL-01, D5-TPL-01
                          ├─ Формы      D2-FRM-01, D1-FRM-01
                          ├─ Чек-листы  D1-CHK-02, D5-CHK-01, D6-CHK-01
                          └─ Реестры/Каталоги  D*-RGS-*, D6-CAT-*
                              └─ Отчёты/Дашборды  D*-RPT-*, D*-DSH-*
                                  └─ Метрики (KPI)  каталог `../boards/01-kpi-framework.md`
```

### Правило наследования (инвариант)

- **Согласованность вниз:** дочерний документ не вводит требований, противоречащих родителю.
  Конфликт SOP ↔ Стандарт разрешается в пользу Стандарта (`03-classification.md`, лестница
  обязательности).
- **Прослеживаемость вверх (traceability):** любой SOP/форма/чек-лист ссылается на процесс и,
  через него, — на политику/стандарт-родитель (поле «Нормативные ссылки» мета-шаблона).
- **Корень один:** вершина дерева — `D7-POL-01` (Миссия/Ценности). Документ, не сводимый к
  корню ни по одной ветке, — кандидат на проверку (`90-audit.md`).

## 11.2. Дерево зависимостей (Dependency Tree)

Зависимость ≠ наследование: документ может зависеть от «соседа» из другого Division. Ниже —
лес зависимостей вокруг ключевых узлов; стрелка `A → B` читается «B зависит от A» (A —
предпосылка B). Полная матрица родитель/ребёнок — `06-matrices.md`, §10.

### Продуктовая цепочка (узел-блокер: методология)

```
D5-POL-01 (Политика качества)
  → D5-STD-01 (Валидация психометрики) ── внешний психометрист
      → D5-SPC-01 (Методология скрининга)  ◀── БЛОКЕР №1
          → D4-SPC-02 (Квиз) ─┐
          → D4-SPC-03 (AI-отчёт) ─┤
          → D5-GDL-01 (Дисклеймер) ─┤
          → D2-SOP-02 (Тексты мини-отчёта) ─┘
              → D2-RGM-02 (Регламент воронки P2)
                  → D4-AIA-01/02 (Промпты) → генерация отчёта (P05)
```

### Комплаенс-цепочка (узел-блокер: gate перед трафиком)

```
D1-POL-02 (Privacy)
  → D1-POL-03 (Данные несовершеннолетних)  ◀── БЛОКЕР запуска трафика
      → D1-RGS-05 (Реестр согласий)
      → D1-FRM-01 (DPIA)
      → D1-POL-07 (Согласия/cookie)
          → D1-CHK-02 (Compliance-gate перед трафиком)
              → P02 (запуск трафика) РАЗРЕШЁН
D1-POL-04 (Хранение/удаление) ┄ параллельная предпосылка D1-POL-03
```

### Данные и метрики (единый источник истины)

```
D4-STD-07 (Именование данных)
  → D4-DAT-01 (Data Dictionary)
      → D4-DAT-02 (Словарь метрик)  ── унифицирует KPI-/KPI_
          → все DSH-борды (исполнимы)
          → D3-SPC-01 (Юнит-экономика)
D4-CLF-01 (Классификаторы ядра) ┄ предпосылка D4-DAT-01
D2-CLF-01/02/03 (MK_/PG_/CELL_) → D2-STD-01 (UTM) → атрибуция P02/P06
```

### Каталоги (узел-блокер: парсер рынка труда)

```
D6-POL-02 (Источники данных) ─┐
D6-CLF-01 (Классификатор профессий) ─┤
D6-GDL-01 (Обезличивание) ─┘
  → D6-CAT-01 (Каталог профессий)  ◀── зависит от парсера (БЛОКЕР №2)
      → карьерный модуль профиля (D4-SPC-01)
```

### Управление документами (мета-контур DMS)

```
D5-POL-02 (Политика управления документацией)
  → D5-PRC-04 (Процедура управления документами, 9 этапов ЖЦ)
  → D5-STD-05 (Именование документов)
  → D5-TPL-01 (Мета-шаблон)
      → D5-RGS-01 (Мастер-реестр)  ── учитывает ВСЕ документы реестра
```

### Три обязательные (жёсткие) зависимости — нельзя обойти

| # | Зависимость | Что блокирует | Почему жёсткая |
|---|---|---|---|
| 1 | `D5-SPC-01` (методология) → продукт | Квиз, отчёт, воронку | Без методологии продукт без основания (блокер №1) |
| 2 | `D1-POL-03` + `D1-CHK-02` → трафик | Запуск платного трафика | Детские данные без режима — регуляторный стоп |
| 3 | `D4-DAT-02` (словарь метрик) → борды | Исполнимость дашбордов | Без формул/единых кодов борды — картинки |

## 11.3. Как деревья используются

- **При создании документа:** найти родителя по дереву наследования → унаследовать рамку →
  проверить жёсткие зависимости по дереву зависимостей (не начинать ребёнка раньше родителя).
- **При изменении:** пройти вниз по наследованию — какие дети требуют пересмотра (каскад
  версий); пройти по зависимостям — что сломается.
- **При аудите полноты:** документ без пути к корню (наследование) или без предпосылок
  (зависимости) — дефект (`90-audit.md`).
- **При планировании (роадмап):** порядок создания = топологическая сортировка дерева
  зависимостей (родитель раньше ребёнка) с приоритетом Must×Critical (`08-roadmap.md`).
