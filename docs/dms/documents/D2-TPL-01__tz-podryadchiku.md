# D2-TPL-01 · Шаблон ТЗ подрядчику по трафику (11 пунктов)

> **Паспорт.** ID `D2-TPL-01` · класс Шаблон (TPL) · Division D2 (Marketing & Sales) ·
> уровень операционный · версия v1.0 · статус: **СОБРАН** (перенос существующего содержания).
> **Источник:** `../../12-traffic-platform-decisions.md`, блок **Ж.3** «Шаблон ТЗ подрядчику
> (собирается за 15 минут)» — перенесено **дословно**, не сочинено.
> **Где упомянут (реестр/карточка):** `../04-registry.md` (строка D2-TPL-01), `../05-cards.md`
> (карточка D2-TPL-01).

Назначение: за 15 минут собрать однозначное, измеримое и атрибутируемое задание подрядчику на
закупку трафика на одну измерительную ячейку `CELL_`. Заполняется по словарям
`MK_/PG_/CELL_/utm_*` (см. `D2-CLF-01`, `D2-CLF-02`, `D2-CLF-03`, `D2-STD-01`).

## Форма ТЗ

```
ТЗ на закупку трафика — ячейка CELL_____________________

1. Канал (MK_):              MK_________ ( _______________ )
2. Рынок:                    СНГ / MENA
3. Ячейка (CELL_):           CELL_<MK>_<PG/LST>_<market>_<NN> + дата
4. Посадочная:               URL ______________  ключ PG_/LST_ ______ (фиксирована на весь прогон)
5. Целевое действие:         EVT_______ / ORDER_______ (измеримо в системе)
6. UTM-шаблон:
     utm_source=<mk_lower>&utm_medium=<cpc|seed|blog|email|msg|ref|organic|pr>
       &utm_campaign=<cell_..._ГГГГММДД>&utm_content=<creative>
     [для MK_REF_*: &ref_id=<REF_>]
7. Бюджет:                    не менее $400 на ячейку
8. KPI и градация:
     CPL:    ≤ $3 зелёный / $3–6 жёлтый / > $6 красный        [ЦЕЛЬ]
     CR пос.: ≥ 40% зелёный / 25–40% жёлтый / < 25% красный
     что считается успехом / средним / неудачей (для вебинара — градация Ж.2)
     (ДРР считает заказчик по сшивке; подрядчик — до CPL/CR посадочной)
9. Запреты:
     — НЕ менять посадочную (смена = новая ячейка);
     — НЕ лить на главную (PG_HOME) платным холодом;
     — НЕ вести холодный трафик на карточку LST_WEB_*_DIAG без носителя доверия;
     — НЕ упоминать названия методик — только рабочие; без обещаний результата вне брендбука;
     — «одна кампания — одна посадочная».
10. Отчёт:                    формат, частота, куда сдаётся (ежедневно расход/CPL + еженедельно CR)
11. Критерий остановки:       бюджет ячейки исчерпан при CPL > красного и 0 заказов
                              → СТОП, разбор; кто объявляет остановку.
```

## Пометки заполнения (из источника)

- Пороги CPL/CR в п.8 помечены в источнике как **`[ЦЕЛЬ]`** — экспертные гипотезы до первых
  данных; пересчитываются фактическим ДРР после каждого такта (`../../12-…` §«Ограничения»).
- Запрет п.9 «только рабочие названия методик» — жёсткое правило проекта (лицензии BFAS/RIASEC
  нет, `CLAUDE.md`, `../../05-risk-compliance.md`).
- Инвариант: `PG_HOME` не бывает основной посадочной платного холодного трафика.
