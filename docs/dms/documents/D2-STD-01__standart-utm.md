# D2-STD-01 · Стандарт UTM-разметки и сквозной атрибуции

> **Где упомянут:** `../04-registry.md` (D2-STD-01), `../05-cards.md` (шаблон карточки).

Правило-девиз: **«одна кампания — одна посадочная»**. Стандарт задаёт закрытый набор
UTM-параметров, чтобы каждый клик был атрибутируем до заказа.

## Словарь UTM (закрытый)

| Параметр | Значение | Пример / правило |
|---|---|---|
| `utm_source` | ключ канала `MK_*` в нижнем регистре | `mk_vk_ads`; ровно один `MK_` на кампанию |
| `utm_medium` | тип (закрытый список): `cpc` · `cpm` · `seed` · `blog` · `email` · `msg` · `ref` · `organic` · `pr` | `cpc` |
| `utm_campaign` | ключ ячейки `CELL_*` + дата запуска | `cell_vk_quiz_20260720`; одна кампания = одна посадочная, смена посадочной = новая ячейка |
| `utm_content` | креатив / вариант | `cr03_pain_fears` (для A/B) |
| `utm_term` | ключевой запрос (только поиск) | контекст / SEO |
| `ref_id` | владелец реф-ссылки (`REF_*` → `user_id`), сохраняется от клика до заказа | обязателен для `MK_REF_*`; deep-link на карточку обязан сохранять `ref_id` |

## Сквозная цепочка атрибуции (через `user_id`)

```
клик (Метрика/GA: client_id, UTM, ref_id)
   → EVT_<landing>: завершённый скрининг / регистрация на вебинар (платформа)
   → EVT_REG (создан user_id)  ← точка сшивки client_id ↔ user_id
   → EVT_PROFILE10_ACTIVATED (активация)
   → ORDER_DIAG → членство (grant) → ORDER_RENEW   (платформа: user_id)
```

Точка сшивки — **регистрация**: анонимный `client_id`/`ym:uid` связывается с `user_id`,
UTM/`ref_id` записываются в атрибуцию заказа. До регистрации факты живут в Метрике/GA, после —
в платформе; витрины считают из фактов (append-only), не хранят чисел.

## Пробел источника (сохранён, не додуман)

Из `../../12-…` §Е.3: **без сшивки `client_id`→`user_id` и импорта расхода из рекламных
кабинетов истинный ДРР по каналу не считается** — до их появления канал ведётся по прокси
(CPL/CR посадочной). Это главный технический блокер учётного контура, а не решённая задача.
