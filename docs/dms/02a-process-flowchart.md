# 02a. Карта процессов компании — блок-схемы

> Раздел 3 модуля DMS, визуальный компаньон к `02-process-map.md`. Снимок 12.07.2026.
> Авторская разработка (Claude Code). Нотация — блок-схема (ГОСТ 19.701-90 / ISO 5807),
> отрисована средствами Mermaid (GitHub рендерит `mermaid`-блоки нативно). Содержание
> перенесено без изменений из `02-process-map.md` (подпроцессы, входы/выходы, роли, документы,
> инварианты); опора на `00-architecture.md` (12 процессов, поток ценности) и `01-divisions.md`
> (Divisions D1–D7). Перекрёстные ссылки на соседние файлы модуля DMS разрешаются после слияния
> веток. Утверждает основатель.

Двенадцать сквозных процессов P01–P12 показаны на трёх уровнях детализации:

- **Уровень 0** — ландшафт всей компании (12 процессов, три группы, поток ценности).
- **Уровень 1** — сквозной поток ценности «спрос → выручка → сеть» с разведением двух потоков.
- **Уровень 2** — детальная блок-схема каждого из 12 процессов (вход, операции, ромбы решений,
  документы, выход).

Группы процессов (по APQC-подходу, `02-process-map.md`): **управляющие** — P01, P12;
**основные** — P02–P08; **обеспечивающие** — P09, P10, P11.

## Легенда нотации

| Фигура | Синтаксис Mermaid | Значение |
|---|---|---|
| Терминал (овал) | `([…])` | вход / выход процесса (старт, финиш) |
| Операция | `[…]` | действие, шаг подпроцесса |
| Подпроцесс | `[[…]]` | вложенный процесс со своей схемой |
| Решение (ромб) | `{…}` | ветвление, вопрос с ответами да/нет |
| Документ / данные | `[/…/]` | документ (S/I/C) или вход-выход данных |
| Хранилище | `[(…)]` | база: факты append-only, витрины, версии |
| Комплаенс-узел | `{{…}}` (шестиугольник) | обязательная проверка детских/психоданных (инвариант P12) |

Связь «процесс ↔ документ» (из `02-process-map.md`): **S** — обслуживает (документ управляет
ходом), **I** — инициирует (процесс порождает документ), **C** — завершает (использование
документа закрывает процесс).

```mermaid
flowchart LR
  T(["Терминал"]) --> O["Операция"]
  O --> SP[["Подпроцесс"]]
  SP --> D{"Решение?"}
  D -->|"да"| Doc[/"Документ S/I/C"/]
  D -->|"нет"| DB[("Хранилище")]
  CG{{"Комплаенс-узел"}}
  Doc --> CG
```

## Уровень 0 — Ландшафт процессов компании

Управляющие процессы задают рамку сверху, обеспечивающие поддерживают ядро снизу, основные
образуют поток ценности от спроса до выдачи и роста сети. Премиальная продажа P04 показана
обособленной веткой — инвариант «Поток-1 не смешивается с Потоком-2».

```mermaid
flowchart TB
  subgraph GOV["Управляющие · задают рамку"]
    P01["P01 · Стратегия и OKR<br/>D7"]
    P12{{"P12 · Комплаенс, риски, защита данных<br/>D1 → D5"}}
  end

  subgraph CORE["Основные · поток ценности"]
    direction LR
    P02["P02 · Генерация спроса<br/>D2"]
    P03["P03 · Воронка P2: скрининг → freemium → апсейл<br/>D2 → D4"]
    P05["P05 · Производство профиля и AI-отчёта<br/>D4"]
    P06["P06 · Подписка и биллинг<br/>D3 → D4"]
    P07["P07 · Сеть экспертов<br/>D6"]
    P08["P08 · Каталоги: профессии/вузы/работодатели<br/>D6 → D4"]
    P04["P04 · Премиум-продажа P1 (high-touch)<br/>D2 / D7"]
  end

  subgraph EN["Обеспечивающие · поддержка ядра"]
    P09["P09 · Найм и адаптация<br/>D1"]
    P10["P10 · Данные и метрики<br/>D4"]
    P11["P11 · AI-контур: промпты, агенты, eval<br/>D4 → D5"]
  end

  %% поток ценности
  P02 --> P03
  P03 --> P05
  P05 --> P06
  P07 --> P08
  P08 -->|"каталоги в отчёт"| P05

  %% управление
  P01 -->|"OKR, бюджет"| P02
  P01 -->|"личный надзор"| P04
  P12 -.->|"согласия, DPIA"| P03
  P12 -.->|"психоданные"| P05
  P12 -.->|"IP, согласия"| P08

  %% обеспечение
  P09 -.->|"люди"| P02
  P10 -.->|"метрики, витрины"| P05
  P11 -->|"генерация отчёта"| P05
  P11 -.->|"анализ сертификатов"| P07

  N1["Поток-1 обособлен:<br/>метрики P1 ≠ P2"] -.-> P04

  classDef gov fill:#ece3f7,stroke:#6b4fa0,color:#1a1a1a;
  classDef core fill:#dbeafe,stroke:#2f6fb0,color:#1a1a1a;
  classDef enable fill:#e3f4e1,stroke:#3f8f4f,color:#1a1a1a;
  classDef note fill:#fff4d6,stroke:#c79100,color:#1a1a1a;
  class P01,P12 gov;
  class P02,P03,P04,P05,P06,P07,P08 core;
  class P09,P10,P11 enable;
  class N1 note;
```

## Уровень 1 — Сквозной поток ценности (спрос → выручка → сеть)

Входящий спрос расходится по каналу на два потока, которые дальше не смешиваются: воронка
самообслуживания (Поток-2) и премиальная продажа по рекомендации (Поток-1). Сеть экспертов и
каталоги замыкают контур, обогащая отчёт.

```mermaid
flowchart TB
  START(["Спрос / контакт"]) --> CH{"Канал?"}
  CH -->|"воронка (self-serve)"| A1
  CH -->|"рекомендация HNW"| B1

  subgraph V2["Поток-2 · воронка самообслуживания"]
    direction TB
    A1["P02 · трафик MK_ / CELL_"] --> A2["P03 · квиз, 6 шкал"]
    A2 --> A3{"N зон риска из 6"}
    A3 --> A4["Мини-отчёт + 3 CTA"]
    A4 --> A5{"E-mail получен?"}
    A5 -->|"нет"| AX(["Выход без лида"])
    A5 -->|"да"| A6["Регистрация · Профиль 10 (freemium)"]
    A6 --> A7{"Апсейл: оплата 360?"}
    A7 -->|"нет"| A8["Freemium-удержание"]
    A7 -->|"да"| A9["P05 · генерация AI-отчёта"]
    A9 --> A10["P06 · подписка / биллинг"]
    A10 --> A11(["Отчёт выдан · подписка активна"])
  end

  subgraph V1["Поток-1 · премиум (high-touch)"]
    direction TB
    B1["P04 · квалификация"] --> B2{"Квалифицирован?"}
    B2 -->|"нет"| BX(["Отказ / отложить"])
    B2 -->|"да"| B3["Диагностика · предложение (50К → 10 млн / £)"]
    B3 --> B4{"Согласовано?"}
    B4 -->|"нет"| B3
    B4 -->|"да"| B5["Оплата · сопровождение (Год рядом / Family Office)"]
    B5 --> B6(["Премиум-клиент"])
  end

  A11 --> NET["P07 сеть экспертов · P08 каталоги"]
  NET -->|"каталоги обогащают отчёт"| A9

  N0["Инвариант: метрики Потока-1 и Потока-2 не суммируются"]
  N0 -.-> V1
  N0 -.-> V2

  classDef note fill:#fff4d6,stroke:#c79100,color:#1a1a1a;
  class N0 note;
```
