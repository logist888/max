# 06. Матрицы связей

> Разделы 7–10 модуля DMS. Снимок 12.07.2026. Авторская разработка (Claude Code). Матрицы
> связывают реестр `04-registry.md` с процессами `02-process-map.md`, Divisions `01-divisions.md`
> и ролями. Утверждает основатель.

Четыре матрицы: **Документ → Процесс** (7), **Документ → Division** (8), **Документ → Владелец**
(9), **Зависимости** (10). Связь «процесс» — по типам S/I/C (обслуживает/инициирует/завершает,
см. `02-process-map.md`).

зависимости (без родителя документ не имеет основания). Полное дерево — `07-trees.md`.

| Документ | Родители (обязательные) | Дети | Жёсткая зависимость (блокирует) |

| D7-RGS-01 OKR | D7-POL-01, D7-RMP-01 | проектные планы, KPI-каталог | Стратегия должна существовать |
| D2-RGM-02 Воронка P2 | D2-RMP-01, D2-POL-01, D4-SPC-02, D5-SPC-01 | D2-SOP-02, D2-FRM-01 | **D5-SPC-01 (блокер №1)**, D1-POL-03 |
| D4-SPC-03 AI-отчёт | D4-SPC-01, D5-SPC-01 | D4-AIA-01/02, D5-STD-02, D5-GDL-01 | **D5-SPC-01 (методология)** |

### Критические цепочки зависимостей (что чему предшествует)

```
D7-POL-01 (миссия) → D7-RMP-01 (стратегия) → D7-RGS-01 (OKR) → планы/KPI
D5-POL-01 → D5-STD-01 (валидация) → D5-SPC-01 (методология) → D4-SPC-02/03 → D2-RGM-02 (воронка)
D1-POL-02 → D1-POL-03 (дети) → D1-RGS-05 (согласия) + D1-CHK-02 (gate) → запуск трафика P02
D4-DAT-01 (Data Dictionary) → D4-DAT-02 (словарь метрик) → DSH-борды (исполнимы)
```

> Два «узла-блокера» проекта прямо видны в матрице: **методология скрининга** (`D5-SPC-01`,
> блокер №1) держит всю продуктовую цепочку; **compliance-gate** (`D1-POL-03` + `D1-CHK-02`)
> держит запуск трафика. Ни один из них нельзя обойти — это жёсткие зависимости, не
> рекомендации.
