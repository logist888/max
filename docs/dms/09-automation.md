# 09. План автоматизации и цифровая экосистема

> Раздел 13 модуля DMS. Снимок 12.07.2026. Авторская разработка (Claude Code). План связывает
> документы с системами хранения, определяет, что автоматизируется и что генерируется AI,
> задаёт правила синхронизации и версий. Опора: практики GitLab (docs-as-code), Notion, Atlassian,
> Linear. Утверждает основатель.

Принцип автоматизации: **документ-как-код там, где важна версия и ревью; система-приложение
там, где важен ввод данных и роли.** Не автоматизировать раньше, чем документ стабилизировался
(автоматизация черновика тиражирует ошибку).

---

## 13.1. Раскладка «класс документа → система хранения»

Целевая экосистема (вводится по мере зрелости, `08-roadmap.md`); на MVP большинство живёт в
git + Google Workspace, как сейчас (`SYSTEM.md`).

| Класс | Первичная система (цель) | Формат | Почему |
|---|---|---|---|
| Политика, Стандарт, Регламент, Процедура, SOP | Git (`docs/`) + витрина Notion | md | Нужны версии, ревью, история; docs-as-code |
| Рабочая инструкция, Гайдлайн, База знаний | Notion / внутренняя вики | md/страницы | Читаемость, поиск, ссылки |
| Шаблон, Чек-лист, Форма | Notion/Google Forms + git-эталон | шаблон/форма | Многократное заполнение, сбор данных |
| Реестр, Классификатор | Notion БД / таблица + git-снимок; критичные (согласия, транзакции) — платформа | таблица/БД | Живые записи, статусы, автоподсчёт |
| Каталог | Платформа mainexperts.online (БД) + WordPress (SEO) | БД/витрина | Продуктовый контент, публичный |
| Дашборд | BI (Data Studio) / платформа; спека — git | борд + md | Живые метрики; борды MMS |
| Отчёт | BI + Google Drive (PDF) | таблица/PDF | Снимок за период, рассылка |
| Дорожная карта, План | Linear/Jira + git-снимок | доска/md | Планирование и трекинг |
| Архитектурный, Спецификация | Git + диаграммы (C4/BPMN/ER) | md + схема | Версия, связь с кодом |
| Договор | Google Drive (подписанные) + Реестр договоров | PDF | Юридические оригиналы |
| AI-артефакт | Git (как код) + OpenRouter/платформа | структ. файлы | Версионирование промптов |
| Data-артефакт | Платформа/БД (`kpi_definitions`) + git-снимок | таблица/БД | Единый источник истины по данным |

> Оговорка: Google Drive не умеет удалять/переименовывать/перезаписывать и не рендерит
> вики-ссылки (`SYSTEM.md`) — поэтому источник истины по документам-как-код остаётся в git, а в
> Drive уходят снимки/PDF (правило двух версий). Notion/Linear/Jira/CRM — целевые системы,
> вводятся на Growth.

## 13.2. Что автоматизируется (ведение) и что генерируется AI

Два разных вопроса: **автоматизация ведения** (реестр сам обновляется из систем) и **AI-генерация
содержания** (черновик пишет модель, человек утверждает). Оба поля есть в реестре (`Авт·AI`).

### Высокий потенциал автоматизации ведения

- **Реестры-факты** (D1-RGS-05 согласия, D3-RGS-01 транзакции, D2-RGS-01 кампании, D6-RGS-01
  эксперты): ведутся событиями платформы (append-only), не вручную.
- **Мастер-реестр DMS** (D5-RGS-01): автоподсчёт покрытия, статусов ЖЦ, дат пересмотра;
  напоминания о плановом пересмотре по критичности (4.3).
- **Дашборды/отчёты** (D*-DSH-*, D*-RPT-*): считаются из фактов через `kpi_definitions`/витрины
  `v_*` (`../10-data-model.md`).
- **Классификаторы** (`MK_/PG_/CELL_`, D2-CLF-*, D4-CLF-01): валидация UTM/событий против
  закрытого словаря автоматически.

### Высокий потенциал AI-генерации содержания (человек утверждает)

- **Паспорта карточек** (`05-cards.md`): AI собирает 30 полей из реестра + шаблона — «да».
- **Отчёты по кампаниям/сети** (D2-RPT-01, D6-RPT-01): AI-нарратив поверх метрик — «да».
- **Профили ролей, чек-листы, шаблоны** (D1-TPL-01, D*-CHK-*): AI-черновик по образцу — «да».
- **Продуктовые/инженерные спецификации, промпты** (D4-SPC-*, D4-AIA-*): AI-черновик —
  «частично» (требует экспертной доводки).

### Низкая автоматизация / нет AI-генерации (только человек)

- **Юридические и методологические** (D1-CTR-*, D1-POL-03, D5-SPC-01, D5-STD-01): ответственность
  и достоверность требуют человека и внешней экспертизы. AI — только вспомогательный черновик под
  строгим ревью.

> Граница AI (инвариант канона, `../boards/00-framework.md`): **AI объясняет/предлагает черновик,
> но не утверждает документ и не меняет нормативную рамку.** Утверждение — всегда роль-владелец
> (поле «Необходимые согласования» карточки). Все AI-генерации документов проходят human review
> (D5-SOP-01) и фиксируются в AI-аудите (D4-RGS-04).

## 13.3. Автоматические связи и синхронизация

| Связь | Как реализуется | Направление |
|---|---|---|
| Документ ↔ мастер-реестр | ID-паспорт в шапке → строка реестра D5-RGS-01 | двусторонняя |
| Документ ↔ процесс | поле «Связанные процессы» → матрица `06-matrices.md` | документ → процесс |
| KPI ↔ словарь метрик | код KPI → `kpi_definitions` (единый расчёт) | метрика → борд/отчёт |
| Событие ↔ реестр-факт | `EVT_/ORDER_` платформы → реестры (append-only) | система → документ |
| Классификатор ↔ разметка | закрытый словарь → валидатор UTM/событий | классификатор → данные |
| Git ↔ Drive | публикация снимка/PDF (скилл `publish`) | git → Drive (правило двух версий) |
| Версия ↔ история | commit/`vX.Y` → раздел «История версий» | автоматически из VCS |

**Правило синхронизации:** источник истины — один на класс (13.1); остальные системы — проекции.
Двойное ведение запрещено (иначе расхождение версий). Публикация в Drive — снимком, не рабочим
файлом (`SYSTEM.md`).

## 13.4. Автоматизация жизненного цикла

| Этап ЖЦ | Автоматизация |
|---|---|
| Создание | шаблон из `D5-TPL-01`, автозаполнение паспорта (ID по схеме, дата, версия) |
| Согласование | маршрут визирования по «Необходимым согласованиям» карточки (Notion/PR-ревью) |
| Утверждение | фиксация утверждающего; смена статуса `Draft→Approved` |
| Публикация | авто-снимок в Drive/витрину, оповещение адресатов |
| Использование | ссылки-трекинг, счётчик применения (где уместно) |
| Изменение/Версия | `vX.Y` из VCS; MAJOR ⇒ полный цикл, MINOR ⇒ упрощённый (4.3) |
| Пересмотр | напоминание по cadence критичности (Cr≤6 мес … Low≤24 мес) |
| Архивирование/Удаление | статус `Deprecated→Archived→Retired`; удаление по retention-политике + акт |

## 13.5. План внедрения (фазами, синхронно с роадмапом)

| Фаза | Что автоматизируем | Инструменты |
|---|---|---|
| **MVP** | git-канон `docs/dms/`, мастер-реестр (таблица), скилл `publish` (git→Drive), реестры-факты на платформе | git, Google Workspace, платформа |
| **Growth** | витрина Notion, AI-генерация паспортов/отчётов, маршруты согласования, словарь метрик из `kpi_definitions` | Notion, OpenRouter/Claude, BI |
| **Scale** | Linear/Jira для планов/бэклогов, CRM для клиентских документов, авто-напоминания о пересмотре, lineage | Linear/Jira, CRM, BI |
| **Enterprise** | сквозной DMS-контур с аудит-логом, интеграция систем, авто-отчётность соответствия | интеграционный слой |

> Роль критика: не строить целевую экосистему (Notion+Jira+CRM+BI) на MVP — это повтор ошибки
> «enterprise раньше данных». На запуске достаточно git + таблицы + платформы; остальное — по
> мере зрелости и по триггерам роадмапа.
