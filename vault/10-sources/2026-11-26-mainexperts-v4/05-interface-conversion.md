# MainExperts. Онтология интерфейсов и конверсий v4.0

**Версия от 26 ноября 2026 года.** Документ описывает продуктовые маршруты для 26 гипотез услуг. В каждом маршруте отдельно заданы потребность, интерфейс, действие, текст CTA, экран, событие и итог для пользователя. 91 сценарий и его локализации хранятся в каталоге данных. Это спецификация для сборки страниц и проверки конверсии.

## Сущности и способ выбора маршрута

| Сущность | Ключ | Как используется |
|---|---|---|
| Поисковый запрос | QUERY_ID | Сохраняет оригинальную формулировку, источник и рынок по факту наличия атрибута |
| Кластер | CLUSTER_ID | Группирует ожидаемый результат и намерение, определяет посадочную |
| Гипотеза услуги | SERVICE_ID | Содержит отдельную задачу, границы и тип исполнения |
| Продукт | PRODUCT_ID | Содержит объём, цену при запуске, сроки, подтверждение результата и правила возврата |
| Функциональный элемент | ELEMENT_ID | Определяет форму взаимодействия и минимальные требования доступности |
| Маршрут конверсии | CONVERSION_ID | Определяет исходный экран, условие, действие, следующий экран, результат и событие |
| Локализованный текст | CONVERSION_ID × LANGUAGE | Задаёт основной и альтернативный CTA и перевод на русский |

1. Первичное соответствие задачи и намерения определяет посадочную и бесплатное действие. Для неоднозначного запроса показывается безопасный основной маршрут, уточнение объекта и источник.
2. Запрос о конкретной организации ведёт к её странице или подтверждённому официальному каналу. Существование бренда или стоимость обучения сами по себе дают контекст для ответа.
3. Явный запрос цены, специалиста или заказа ведёт на карточку конкретного продукта при совпадении предмета запроса и объёма услуги. Поддерживаемый маршрут, доступность и цена проверяются до отображения кнопки заказа.
4. Бесплатный результат предоставляется сразу. Для сохранения, уведомлений и исполнения оплаченного заказа собираются только данные, нужные этой операции.
5. Дополнительная помощь предлагается при конкретном триггере, например при конфликте двух правил, иностранной квалификации или нескольких офферах. Пользователь может открыть первоисточник и продолжить сам.
6. Для публичного процесса используются подтверждённый адрес, имя получателя, дата сверки и зона действия. При неизвестной ссылке показываются контакты учреждения и статус проверки.
7. Для партнёра показываются специализация, полномочия там, где они требуются, предельный срок и сторона, которая принимает деньги и претензии.

Платёж оператору подачи или университету отображается отдельно. Подачу выполняет заявитель в своём кабинете.

## Оформление и исполнение

1. Заказчик видит продавца, цену с валютой, пределы объёма, пример результата, срок с поясом и условия возврата. Цена и доступность фиксируются в заказе. Для услуги со сложным вводом перед оплатой подтверждается только пригодность обращённого случая без избыточного сбора файлов.
2. Заказ создаётся один раз с ключом идемпотентности. Платёж сверяется с подписанным событием провайдера или ответом проверяемого запроса. Возврат, отклонённый платёж и повторная доставка учитываются как отдельные события.
3. Загрузка документов происходит в отдельном экране с минимальным сохранением, ограничением доступа и сроком удаления. Ссылки на исходники помечаются их версией и датой. В аналитику передаются только технические ключи и состояния.
4. Заказ получает статус оплаченного, принятого в работу, готового, принятого пользователем или возвращённого. Выход из оплаченного сценария обеспечивают автоматическая проверка срока, доступ к результату и эскалация в поддержку.
5. Партнёрский переход содержит явное согласие на передачу необходимых данных. Статус заказа и возврат сверяются с данными партнёра. Клик по внешней ссылке сам по себе учитывается как переход.
6. В государственный, институциональный или экзаменационный процесс пользователь входит напрямую. Для таких сборов используются отдельные обозначения и события аналитики.

## События и измерение

| Событие | Точка регистрации | Основная метрика |
|---|---|---|
| `free_result_rendered` | Приложение вернуло применимый ответ и источник | Результативные сессии / релевантные входы |
| `official_handoff_clicked` | Нажата размеченная официальная ссылка | Переходы / показы ссылки, отдельно успешность внешнего контакта |
| `qualified_offer_opened` | Открыты условия при наступлении триггера | Открытия / сессии с наступившим триггером |
| `checkout_started` | Пользователь дошёл до подтверждённых условий и начал оформление | Начатые оформления / релевантные показы карточки |
| `payment_confirmed` | Плательщик, сумма и валюта сверены на сервере | Подтверждённые покупки / начатые оформления |
| `partner_handoff_clicked` | Нажата карточка проверенного партнёра | Переходы / показы партнёра |
| `partner_order_confirmed` | Партнёр прислал подтверждённый идентификатор заказа | Заказы / валидные партнёрские переходы |
| `fulfilment_delivered` | Результат доступен пользователю | Срок и полнота исполнения по заказу |
| `fulfilment_accepted` | Заказчик подтвердил результат либо наступило оговорённое условие закрытия | Принятые заказы / оплаченные заказы |
| `order_refunded` | Подтверждён полный или частичный возврат | Возвраты, сумма, причина и медиана времени до возврата |

Варианты конверсии сравниваются внутри одной задачи, локали и источника трафика. Деноминаторы и правило атрибуции фиксируются до эксперимента. События включают анонимный идентификатор сессии либо идентификатор заказа, страницу, коды задачи, CTA, продукт, язык, рынок при его наличии и дату версии. Сырые тексты документов, визовые сведения, паспортные данные и текст обращения в аналитику не передаются.

Для информационных кластеров контрольный вариант показывает ответ и ссылку на источник. Опытный вариант добавляет действие по выявленной следующей задаче. Критерии проверки включают успешность бесплатного ответа, долю подтверждённых покупок среди релевантных входов, качество исполнения, жалобы и возвраты. Для прямых коммерческих входов можно сравнить карточку с образцом результата и компактную карточку, сохраняя одинаковые условия покупки.

## Реестр элементов и правил

Для каждой строки в файле `conversions.tsv` заданы основной и альтернативный тексты CTA, триггер, место, входные поля, следующий экран, бесплатный и платный результаты, получатель платежа, способ исполнения, событие, метрика и эксперимент. Файл `conversion_intents.tsv` связывает 14 намерений с 26 гипотезами услуг. Реестр поддержки языка и локализованные CTA поставляются как отдельные связанные таблицы.
