# Структура страниц: Авиасейлс и Booking.com (12.11.2026)

Метод: загружена HTML-разметка по одному образцу каждого типа страницы, разобраны блоки, JSON-LD, интерактивные «острова» (Astro) и состав элементов. Образцы: aviasales.ru и booking.com (локаль ru). Динамика определялась сравнением двух загрузок одной страницы с интервалом около минуты плюс анализом содержимого блока. Это проверка на одном образце, не на выборке.

Первичный разбор (разделы 1–3) сделан по загрузке с сервера. Разделы 6–8 добавлены 12.11.2026 по файлам, которые вы сохранили в браузере (12 страниц: 5 Skyscanner, 7 Booking.com). Сохранённая страница уже отрисована, поэтому видны блоки, которые подгружаются скриптами.

Не вошло: sitemap и robots.txt Skyscanner (в архиве их нет), весь пользовательский поток поиска и брони.

## 1. Авиасейлс: общий каркас (одинаков у всех типов)

Технология: Astro (разметка собирается на сервере, интерактивные части подгружаются «островами» с указанием момента загрузки). Главное для SEO: текст блоков, цены и ссылки есть в исходном HTML, робот видит их без исполнения скриптов.

| Элемент | Состав | Статика / динамика |
|---|---|---|
| Шапка | Избранное, Профиль, Поддержка; форма поиска билетов (остров `AviaFormContainer`, поля город отправления, город прибытия, даты) | Шапка статична; форма интерактивна, начальные значения подставлены под страницу |
| Заголовок H1 | «Авиабилеты из X в Y» | Шаблон + сущности, статично |
| Хлебные крошки | BreadcrumbList (микроразметка) | Статично |
| Подвал | Продукты (экскурсии, отели), партнёры, документы | Статично |
| Мета | title с ценой («…от 1 694 ₽»), description с ценой, canonical, 17 hreflang, Open Graph | title и description динамические (цена); остальное статично |
| Микроразметка | Organization, WebSite, WebPage, BreadcrumbList, Product (цена), FAQPage; по типу страницы: City, Country, Airport, Airline, Flight | Product и FAQ зависят от данных |
| Прочее | Островы `LinksInModal` (6 шт.), `Web2AppContainer` (переход в приложение) | Интерактив |

### 2.7 Отели, экскурсии, справка

Отдельная система (другой шаблон, без Astro, состояние в `window.__`).
- Отель (47 492 URL): микроразметка Hotel/LocalBusiness, цены, фото, отзывы, форма брони. Основная часть содержимого грузится данными, в статичной разметке мало ссылок (8).
- Экскурсии (4 406 URL): ItemList, 98 изображений, чипы фильтров, карточки с ценами.
- FAQ (44 URL): статья без микроразметки, контактная форма. Статичен.

### 3.3 Состав индекса по sitemap (robots.txt: 443 sitemap-индекса)

Всего 27 751 дочерних sitemap, 44 локали, на локаль ru 744 файла. В обследованных образцах файл содержит около 49 990 URL (страны: 231, аэропорты: 3 033). Верхняя оценка: порядка 1,4 млрд URL во всех локалях, около 37 млн на локаль ru. Это граница сверху, а не факт: заполнение каждого файла не проверялось.

## 4. Выводы для портала MainExperts (вывод, а не факт)

1. Оба сервиса строят SEO на справочных сущностях со статичной основой (страна, город, аэропорт, регион) и живой «витриной» (цены, табло, число отелей). Результаты поиска и бронь закрыты.
2. Типовой набор блоков на странице сущности: краткие показатели → витрина предложений → график динамики → перелинковка на соседние сущности → вопросы и ответы с FAQPage → материалы журнала → навигация. Вопросы и ответы заполняются шаблоном из данных, поэтому уникальность текста низкая.
3. Перелинковка занимает основную массу ссылок страницы (на узловой странице «Москва» 325 ссылок, на рядовой маршрутной около 176), то есть именно она делает индекс связным.
4. Аналоги для вашей модели: страна, город, вуз, программа, профессия. Как у Авиасейлса, живую часть (цены, даты приёма, рейтинг) можно держать динамической, а модули программ оставить закрытыми.

## 5. Ограничения

- Один образец на тип страницы, один момент времени.
- Динамичность определена по двум загрузкам с интервалом около минуты; блок, который не изменился за минуту, мог бы измениться за сутки. Блоки «DIFF» частично отличались и из-за служебных атрибутов разметки.
- «Тип» (С/Д) отнесён по содержанию блока, это экспертное отнесение, а не измерение.
- Реальное число проиндексированных страниц в поисковиках не измерялось.

## 6. Skyscanner: пять сохранённых страниц

Источник: `skyscanner.net`, английская версия (Великобритания). Метатега `robots` на страницах нет, то есть индексация не запрещена. Общее у всех: canonical, 76 вариантов hreflang, микроразметка Product + BreadcrumbList + FAQPage, три iframe, 177–185 кнопок, 8 полей ввода, одна таблица.

|---|---|---|

**Отличия типов.**
- Маршрут (`/routes/lond/pari/london-to-paris.html`): сильнее всего завязан на цену и расписание, блок «Handy information about London airport» и «Paris airport: good to know» даёт уникальный текст по обоим концам.

## 7. Booking.com: семь сохранённых страниц

Общее: hreflang 92 (у отеля 46), метатег `robots` разрешает индексацию (`index,follow,max-snippet:-1,max-image-preview:large`), кроме страницы поиска.

**Важный факт.** Страница результатов поиска (`/searchresults.ru.html`, «Дубай: найдено 14 814 вариантов») имеет `robots: noindex,follow`. Канонический адрес общий для всех запросов. Это прямое подтверждение того, что результаты поиска закрыты от индекса, а «хлебные» справочные страницы открыты.

Микроразметка: страна, город, достопримечательность и аэропорт имеют общий набор WebSite + Corporation/Brand + ImageObject + Person + CollectionPage; плюс по типу Country или City, BreadcrumbList (у достопримечательности вместо него LandmarksOrHistoricalBuildings), у отеля Hotel, у маршрута City.

## 8. Сводка для решения по портале (вывод)

1. Оба конкурента держат справочные страницы сущностей открытыми, а результаты поиска закрывают (Booking: `noindex`, Aviasales: запрет в robots.txt). Рекомендация по структуре из созвона («хлебные крошки» открыть, динамическую выдачу закрыть) подтверждается практикой.
2. Единый рецепт страницы сущности: короткие показатели → витрина предложений (динамика) → подборки по тематике → FAQ с микроразметкой, который собирается шаблоном из данных → перелинковка на соседние сущности → редакционный текст на сущность. Для Skyscanner редакционный блок заметно больше, чем у Aviasales и Booking, и он содержит уникальный текст про место («Best time to go», «Getting to…»).
3. Самый тонкий по содержанию тип: страница авиакомпании у Skyscanner и страница маршрута у Booking. Уникальность им даёт цена и расписание, а не текст.
4. Для MainExperts. Прямые аналоги: страна, город, вуз, программа, профессия. Шаблон блоков можно взять почти дословно: показатели → подборка программ с индексом совместимости → динамика (стоимость, сроки приёма) → FAQ → соседние сущности → экспертный текст. Модули программ в этот шаблон не входят ни у кого из трёх конкурентов (у них нет аналога «внутренности билета»), что поддерживает позицию Максима.

## 9. Ограничения второй части

- Сохранены по одной странице каждого типа в один момент времени; динамичность определена по содержанию блоков, повторной загрузки не было.
- Skyscanner: sitemap и robots.txt не получены, поэтому объём индекса Skyscanner по-прежнему не оценён.

## 10. Skyscanner: sitemap и robots.txt (получены 12.11.2026 от вас)

**Sitemap** (`skyscanner.net/sitemap.xml`, индекс, 81 КБ). Известно:
- 822 дочерних файла sitemap, из них 793 с локалью `en-gb` и 29 «custom». Это индекс только британской версии; индексы других локалей в файл не вошли.
- Типов файлов 75. По числу файлов: отели (`hotels-hotel-detail` 371, `hotels-near-place` 39, `hotels-in-city` 21 и десятки тематических «отели с бассейном/парковкой/Wi-Fi/животными»), перелёты «из аэропорта в регион» (44) и «из города в регион» (43), прокат авто (25 типов авто в городе, 14 по провайдерам и др.), маршруты «из города/аэропорта в страну» (19), «откуда-куда» (15), авиакомпании (`flights-airline`, `airline-flights-to-city`/`to-airport`), страны, регионы, континенты, пакетные туры, трекер рейсов, последние предложения, гольф-хабы.
- Страницы отелей (371 файл из 822, 45%) это основной объём, так же как у Aviasales (отели 36% URL) и у Booking.

**Объём.** Дочерние файлы закрыты капчей, количество URL внутри не измерено. Верхняя граница по стандарту sitemap (до 50 000 URL в файле): 822 × 50 000 ≈ 41 млн URL для en-gb. Это не оценка, а потолок; реальное число может быть намного ниже. Чтобы получить цифру, нужно сохранить 3 файла: `en-gb_hotels-hotel-detail_1_sitemap.xml`, `en-gb_flights-from-city-to-region_1_sitemap.xml`, `en-gb_routes-from-to_1_sitemap.xml` (ссылки вида `https://www.skyscanner.net/<имя>`).

**robots.txt: что закрыто для всех роботов.**
- Параметры поиска: `?origin=`, `?adults=`, `?cabinclass=`, `?outboundDate=`, `?checkin=`, `?pick_up_date=`, `?searchoffer=`, `?source=`, `?p1=`…`?p4=`.
- Представления цен: `/prices-calendar`, `/*/month-view/`, `/*/year-view/`, `/*/day-view/`, `/*/browse-view/`, `/*/worldwide.html`, `/*/selected-flights.html`.
- Служебное: `/deeplink*`, `/dataservices/*`, `/sem/*`, `/g/*`, `/book/*`, `/inspiration/*`, селекторы (`/origin-selector*`, `/date-picker*`).
- Результаты и посадочные отелей и авто: `/hotels/search*`, `/hotels/q/*`, `/hotels/book/*`, `/carhire/results/*`, `/package-holidays*`.
- Страницы вида «routes-from-…» и «cheapest-flights-…», «airfares-…», «tarifs-…» на десятках языков (дубли городских посадочных страниц) закрыты.

**Что остаётся открытым:** маршруты (`/routes/lond/pari/london-to-paris.html`), «рейсы в страну/город/аэропорт» (`/flights-to/...`), авиакомпании (`/airline/...`), отели по городам и тематикам.

**Выводы.**
1. Skyscanner закрывает параметры поиска и «календарные» представления цен, то есть именно то, что генерирует бесконечное число страниц. Открытым оставляет конечный набор сущностей. Правило то же, что у Aviasales (Clean-param, запрет `/search`) и Booking (`noindex` на поиске).
2. Закрыты и однотипные дубли справочных страниц (разные формулировки «cheapest flights» на разных языках). Значит, у конкурентов тоже есть риск дублей, и они им управляют через robots.txt.
3. Для MainExperts: запрет по параметрам фильтров и сортировки закладывается сразу (аналог `origin`, `adults`, `checkin`), а страницы сущностей остаются открытыми.
