## 9. Сводные выводы (В)

1. **Что есть у всех.** Страницы стран, городов, отелей, редакционный раздел; поиск закрыт от индекса; canonical, hreflang, хлебные крошки; витрина с ценами; перелинковка на соседние сущности.
2. **Чего нет у конкурентов.** Ни у кого нет открытых «внутренностей» продукта: ни детализации билета, ни номерного фонда за пределами карточки отеля. Для вашей идеи не открывать модули программ это не расхождение с практикой.
3. **Различия в стратегии.** Aviasales: небольшой индекс (131 тыс. URL) на маршрутах и отелях, основной небрендовый трафик из журнала. Skyscanner: самый богатый текстом шаблон страницы (в среднем 8–20 блоков), закрытие дублей через robots.txt. Booking: максимальный масштаб (до десятков миллионов страниц), охват через отели, тематические подборки (392 индекса из 443) и отзывы.
4. **Для MainExperts.** Реалистичный ориентир по масштабу это Aviasales (≈ 0,1–1 млн страниц), а не Booking. Бренда и журнала нет, значит, на старте основа трафика должна быть небрендовой: страницы сущностей плюс статьи. Рекомендую шаблон Skyscanner по насыщенности текстом, схему закрытия параметров из Aviasales и Skyscanner.

## 10. Ограничения

- Структура страниц: один образец на тип в один момент времени; динамичность определена по содержанию блоков.
- Skyscanner: число URL в sitemap не измерено; Booking: потолки умножены на 50 000, реальное число ниже.
- Цифры трафика и индекса оценочные (PR-CY), датированы по-разному; у Skyscanner данные индексации от мая 2025.
- Для Booking не проверялись параметры запроса и список закрытых разделов robots.txt (файл 40 КБ, разобран только список sitemap).
- Структура страниц Booking сохранена в русской локали, Skyscanner в английской (UK), Aviasales в русской.
