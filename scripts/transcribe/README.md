# Транскрипция по говорящим

Превращает запись созвона (Google Meet, Zoom, диктофон) в текст, где у каждой
реплики стоит говорящий и таймкод. Работает локально на процессоре: ни ключей,
ни отправки записи наружу. Это существенно — на записях идут имена клиентов,
цены и данные несовершеннолетних.

## Установка

```bash
scripts/transcribe/setup.sh
```

Ставит ffmpeg, `faster-whisper`, `sherpa-onnx` и две модели диаризации (35 МБ).
Модель распознавания (1.6 ГБ) скачивается сама при первом запуске. Контейнер
эфемерный — после пересоздания скрипт запускается заново.

## Запуск

```bash
python3 scripts/transcribe/diarize_asr.py raw/встреча.webm -o transcripts/
```

Полезные ключи:

| Ключ | Смысл |
|---|---|
| `-s 4` | известно число говорящих — задать явно, точность выше |
| `--threshold 0.45` | в авторежиме: ниже порог → больше голосов |
| `--beam 5` | точнее распознавание ценой ~1.5× времени |
| `--names names.json` | подставить имена вместо «Говорящий 1» |
| `--no-diarize` | сплошной текст без разделения по голосам |
| `-l en` | другой язык (по умолчанию русский) |

На выходе четыре файла: `.md` (для чтения и работы), `.txt` (компактно, под
загрузку в модель), `.srt` (субтитры к видео), `.json` (машинная обработка).

## Имена вместо номеров

Диаризация различает голоса, но не знает, как зовут людей. Порядок такой:
сначала прогон даёт «Говорящий 1…N», затем по началу записи (представления,
обращения по имени) человек составляет карту:

```json
{"0": "Максим", "1": "Игорь", "2": "Анна"}
```

и файл пересобирается с `--names`. Промежуточные результаты кешируются
в `transcripts/.work/`, повторный прогон занимает секунды.

## Как устроено

| Шаг | Инструмент | Что делает |
|---|---|---|
| 1 | ffmpeg | контейнер → WAV 16 кГц моно |
| 2 | sherpa-onnx: pyannote segmentation-3.0 + CAM++ | размечает, кто и когда говорит |
| 3 | faster-whisper large-v3-turbo (int8) | распознаёт речь с таймкодами по словам |
| 4 | сшивка | слово получает голос по наибольшему перекрытию, слова собираются в реплики |
| 5 | экспорт | md / txt / srt / json |

## Чего ждать по скорости и качеству

Скорость на 4 ядрах — примерно длительность записи (85 минут записи ≈ 1,5 часа
расчёта), диаризация добавляет 5–10 минут. Память — до 4 ГБ.

Известные ограничения, они же места ошибок:

- **Перекрывающаяся речь.** Когда двое говорят разом, реплика уйдёт одному.
- **Короткие вставки** («да», «угу») часто липнут к соседнему голосу.
- **Похожие голоса** в авторежиме могут слиться в один — лечится ключом `-s`.
- **Термины, имена, англицизмы** распознаются с ошибками; числа и суммы
  перед использованием сверяются с записью.
- **Галлюцинации** на тишине и музыке: VAD их режет, но не полностью.

Транскрипт — сырьё для работы, а не документ. Цифры и цитаты, идущие
в материалы клиентам, проверяются по исходной записи.
