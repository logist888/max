# Борд 13 · System Map — MainExperts

Интерактивная карта архитектуры маркетинга **Traffic → Platform → Decisions** (Поток-2, воронка семей).
Production-ready React SPA: не презентация, а инженерная документация системы, которую можно
использовать ежедневно (CMO, Growth Lead, аналитики, разработчики, подрядчики).

Источник данных — `docs/12-traffic-platform-decisions.md` (снимок 08.07.2026). Это тринадцатый
артефакт после документов 01–12, отсюда — «Борд 13».

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
```

Прочие скрипты:

```bash
npm run build      # tsc --noEmit + сборка (dist/)
npm run typecheck  # только проверка типов
npm run preview    # предпросмотр собранной версии
```

Стек: **Vite + React 18 + TypeScript (strict, без `any`)**, граф на **@xyflow/react** (React Flow),
анимации на **Framer Motion**. Раскладка — собственная детерминированная слоистая (swimlane),
без ручных координат.

## Что умеет

- **Архитектура за 30 секунд.** По умолчанию все семь слоёв свёрнуты в стек из 7 карточек-слоёв —
  это вся система сверху вниз. Клик по слою (или строке в левом рельсе) раскрывает детали.
- **Найти объект за секунды.** Поиск (`⌘K` / `Ctrl+K`) по кодам, названиям, типам, каналам, рынкам,
  ячейкам CELL, событиям, решениям, правилам.
- **Все зависимости.** Инспектор справа показывает свойства, входящие/исходящие связи, правила,
  решения, запреты и структуру истории изменений. Клик по связи переносит к объекту.
- **Поток данных.** Слой ANALYTICS: рекламная площадка → GA/Метрика → платформа → витрина →
  дашборд → Decision Engine, каждая стрелка подписана; пробелы контура помечены.
- **Правила принятия решений.** Слой DECISIONS: метрика → порог (светофор) → решение → действие.
- **Запреты.** Недопустимые связи источник→посадочная — красный пунктир с причиной (тумблер «Запреты»).
- **Фильтры.** Рынок, язык, источник, температура, тип посадочной, статус, владелец.
- **Легенда, мини-карта, zoom/pan.**

## Data-Driven архитектура

Ни одного доменного объекта внутри компонентов. Любой источник (MK_), посадочная (PG_/LST_),
правило, событие, ячейка (CELL_) добавляется **только** правкой словарей в `src/data/*` — и объект
сам появляется во всех местах интерфейса (граф, инспектор, поиск, фильтры, легенда). Компоненты
умеют отображать модели, но ничего не знают о конкретных MK/PG/CELL.

### Поток данных в приложении

```
data/*  ──►  utils/graphBuilder  ──►  DOMAIN_GRAPH (узлы + типизированные рёбра)
                                         │
   state (store: слои, фильтры, выбор) ──┤
                                         ▼
                       utils/viewGraph.composeView
             (сворачивание слоёв, агрегация рёбер, приглушение фильтром)
                                         │
                       utils/layout.layoutLayered  (swimlane + барицентр)
                                         ▼
                              ViewGraph  ──►  features/canvas/Graph (React Flow)
```

### Доменная модель (единственный источник истины)

`src/types/domain.ts` — строгие интерфейсы всех сущностей:
`TrafficSource` · `Landing` · `FlowStep` · `AnalyticsNode` · `Metric` · `Decision` · `Cell` ·
`Rule` · `ContractorTemplate` · `LayerDef`. Граф — в `src/types/graph.ts`:
`GraphNode` · `GraphEdge` · `RelationType` · `DomainGraph` · `ViewNode` · `ViewEdge` · `ViewGraph`.

Цепочка сущностей документа воспроизведена связями графа:

```
MK_ → REF_ → PG_ → LST_ → Landing Event → Registration → Activation → Order →
Membership → Renewal → Analytics → Decision → CELL
```

## Слои (сверху вниз)

`TRAFFIC → LANDINGS → PLATFORM → ANALYTICS → DECISIONS → CELL → CONTRACTOR`.
Каждый слой визуально отделён (цвет-акцент) и сворачивается независимо.

## Инженерные решения

- **Слоистая раскладка вместо dagre.** Архитектура по своей природе слоистая (swimlane). Чистая
  раскладка по длиннейшему пути (dagre) разнесла бы линейную цепочку PLATFORM на 10 рангов и
  «утопила» бы слои CELL/CONTRACTOR, связанные только контекстными рёбрами. Собственная раскладка
  (`utils/layout.ts`) даёт гарантированные горизонтальные полосы по `layer.order` + барицентр для
  уменьшения пересечений. Полностью автоматическая: перестраивается из данных, координаты не задаются.
- **Категории видимости рёбер.** `ALWAYS` (структурные), `SECONDARY` (тумблер «Доп. связи»),
  `FORBIDDEN` (тумблер «Запреты»), `CONTEXTUAL` (только для выбранного узла). Интерфейс не выглядит
  перегруженным; детали раскрываются постепенно.
- **Сворачивание слоёв = агрегация графа.** `composeView` заменяет узлы свёрнутого слоя одним
  агрегатом и сворачивает межслойные рёбра в `layer_flow` с подсчётом. Отсюда «архитектура за 30 секунд».
- **Единые слои-компоненты.** Вместо семи статических компонентов (`TrafficLayer`, `LandingLayer`…)
  — один data-driven рендерер полос и `LayerRail`. Это прямое следствие правила «никаких статических
  карточек, компоненты не знают о конкретных объектах».
- **Строгая типизация.** `strict`, `noUnusedLocals`, `any` запрещён; связи типизированы через
  `RelationType`.

## Известные ограничения и слабые места

- Раскладка — эвристика (барицентр, несколько проходов), не оптимизатор пересечений; на очень
  плотных полосах возможны пересечения рёбер.
- Данные ячеек CELL_ — примерные `[ОЦЕНКА]` для демонстрации; реальные заводятся так же (только данными).
- История изменений — структура предусмотрена, данных пока нет (append-only слой не подключён).
- Один бандл ~170 КБ gzip (React Flow + Framer Motion); код-сплиттинг не делался (внутренний инструмент).
- Мобильный режим ограничен (левый рельс скрывается < 900px); инструмент рассчитан на десктоп.

## План развития

- **v2:** сохранение состояния (URL/localStorage: раскрытые слои, фильтры, выбор), экспорт в PNG/SVG,
  живые метрики на ячейках (подключение витрины ДРР из `docs/10`), подсветка «пути» от источника до заказа.
- **v3:** редактор словарей в интерфейсе с валидацией (правило ≥ $400, «одна кампания — одна
  посадочная»), реальная история изменений (append-only), диффы версий, роли/доступ (RBAC из
  `boards/02-roles-access.md`), связь со сквозной атрибуцией и импортом расхода.
